## C-1：主戦場を Cowork に変更

### 判断の根拠

Claude Code / Cowork はスキルのフォルダを監視しており、**SKILL.md の変更はセッション中に反映される**。
必要なら `/reload-skills` で明示的に読み直させることもできる。

一方チャットはスキルがAnthropicサーバー側にあるため、Claudeがファイルを書き換えられない。
修正のたびに ZIP再作成 → アップロード → セッション再起動 が必要になる。

| | Cowork / Code | チャット |
|---|---|---|
| スキルの実体 | `~/.claude/skills/` | Anthropicサーバー |
| Claudeによる編集 | 可能 | 不可 |
| 修正の反映 | セッション中に反映 | 再アップロード＋再起動 |
| 改善ループ | **閉じる** | 閉じない |

### 運用フェーズ

| フェーズ | 場所 | 目的 | 移行の目安 |
|---|---|---|---|
| **育成期** | Cowork | 使う → 記録 → 直す → すぐ試す を高速で回す | — |
| **安定期** | Cowork ＋ チャット | 完成した版をチャットにも配布 | 改善ログの未対応が2ヶ月出ない |

育成期にチャットを使わない理由は、1回の修正にかかる手間が10倍以上違い、
その差が「改善が続くか放置されるか」を分けるため。

## C-2：改善プロトコル

### 原則：**記録は自動、書き換えは承認制**

| やること | 誰が | 自動か |
|---|---|---|
| 期待どおり動かなかった事実を記録する | Claude | **自動** |
| 修正するかどうか決める | 人 | 手動 |
| 修正案を出す | Claude | 依頼時のみ |
| 修正を承認する | 人 | 手動 |
| SKILL.md を書き換える | Claude | 承認後のみ |

### なぜ書き換えを自動にしないか

1. **n=1の一般化で劣化する。** 1回の失敗でルールを書き換えると、他のケースを壊す。
2. **差分レビューが挟まらない。** いつ何が原因で挙動が変わったか追えなくなる。
3. **gitと乖離する。** 手元だけが勝手に育つと、何をcommitすべきか分からなくなる。
4. **チャット版と乖離する。** 安定期に入ると2系統の挙動が食い違う。

### 実装

SKILL.md 末尾に定型ブロックを組み込む。内容は
[`skill-md-improvement-protocol.md`](skill-md-improvement-protocol.md) を参照。

記録先は [`docs/feedback.md`](../feedback.md)。

### 棚卸しルール

- 月1回、または未対応5件で棚卸しする
- **同じ原因が2回以上出ているものを優先**する
- 1回限りの事象は原則そのまま置く
- 反映したら `metadata.version` / `plugin.json` / CHANGELOG / git tag を揃える
