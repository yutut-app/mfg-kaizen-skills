## 1. 何を確かめるか

2つのことを確かめる。

| 区分 | 確かめること | 基準 |
|---|---|---|
| 再発防止 | 2026-09-22 のレビューで出た13点の失敗が、事例を変えても再発しない | 第4章 R1〜R13 |
| 追加規則 | v1.8 系の実使用で起きた失敗が再発しない（入口の装置、継ぎ目、数値、図、教材） | 第4章 R14〜R23 |
| 汎用性 | 新しい・初めての案件でも、入口で正しく動く（推測値を作らない、確認すべきことを確認する、見本を写さない、指摘を記録する） | 第5章 G1〜G4 |

13点の失敗は、QCストーリーで改善活動の報告資料・教材を作ったときに実際に起きたもの。
各基準の「不合格の例」がその失敗の形。

判定する人に、この文書以外の改訂の経緯は要らない。実行するセッションにこの文書を渡すかは任意

## 3. 判定の決まり

### 値は4つ

| 値 | 意味 | 合格に数えるか |
|---|---|---|
| **合格** | 基準の条件をすべて満たす | 数える |
| **不合格** | 条件のどれか1つでも満たさない | 数えない |
| **判定不能** | その基準を見るべき実行なのに、出力がそのステップまで届かなかった | **数えない**。届かなかった理由を書く |
| **対象外** | その実行では見ない基準（第2章の表で「判定する基準」に入っていない） | 集計に入れない |

判定不能と対象外を混ぜない。**見るべきものが見られなかったのが判定不能、はじめから見ないのが対象外。**

### 根拠の書き方

合格・不合格・判定不能のどれにも、**出力のどこを見たか**を書く。

- 資料なら「スライド5」「表：候補と検証結果」のように場所を書く
- 応答なら「3回目の応答」のように順番を書く
- 該当箇所を1行以内で引用してよい
- 不合格なら、満たさなかった条件の記号（例：R4(b)）を書く

### 全体の合格

**全実行で、判定する基準がすべて合格。** 不合格または判定不能が1つでもあれば、第8章の手順に進む。

## 4. 合否基準：再発防止（R1〜R13）

各基準の条件は **すべて満たして合格**。

| # | 失敗の形 | 合格の条件 | 不合格の例 |
|---|---|---|---|
| R1 | QCストーリーを順番固定の8ステップとして扱う | (a) 案件に合わせて組んだステップの並びが示されている (b) 現状把握が「規模をつかむ（目標設定の前）」と「仮説を検証する（要因解析の後）」の2回置かれている。置かない場合は理由が1行ある (c) 「8ステップを順に行う」と固定する記述がない | 8ステップを番号順に1回ずつ並べ、組み替えの検討がない |
| R2 | 道具をQC7つ道具・新QC7つ道具の中からしか選ばない | (a) 依存関係のない計画にアローダイアグラムを使っていない (b) QC7・新QC7以外の道具（ガントチャート・表など）を使うとき、7つ道具と名乗っていない (c) より分かりやすい道具で同じ判断が出せる場面で、7つ道具に固執していない | 並行作業しかない計画にアローダイアグラムを描く |
| R3 | 要因解析の段で真因を先に決める | (a) 特性要因図など要因を出す段で、「真因」の語、赤字・丸印などの強調を使っていない (b) 「真因」の語は、層別・散布図などの検証の後に初めて使っている (c) 外した候補が1件以上、外した根拠（件数と母数、または相関の有無）付きで残っている (d) 検証した候補が全部「当たり」ではない。全部当たりなら、検証の設計を見直した旨が書かれている | 特性要因図に赤字で「真因」と書き、検証した候補が全部当たり |
| R4 | 目標の削減率を逆算で置く | (a) 項目ごとの削減見込みが、要因ごとの根拠（層別の率など）から出ている (b) 項目ごとの削減後の件数＋対象外の件数＝目標件数、が一致する (c) 目標の率＝目標件数÷母数、が一致する (d) 現状から期限までの月次の段がある (e) 80%を超える減少率には根拠が書かれている (f) 月次の各段に、その時点で効く取り組みが書かれている | 目標の率から「69%減」を逆算で置き、項目別の積み上げがない |
| R5 | テーマ選定で件数の1位しか見ない | (a) 候補を件数だけでなく「自工程で減らせるか」「対策の難易度」でも比べている (b) 1位以外を検討した記録、または1位で問題ない理由がある | 件数1位をそのままテーマにし、減らせるかの検討がない |
| R6 | 原因・対策が現実的でない | (a) 出た原因を、事例の物差し（第6章）と照らして、非現実的なものが0件 (b) **発生の仕組み（中骨）を書かずに、管理の不備（点検・校正の周期、清掃頻度、標準書の記載漏れなど）だけを原因として置いた箇所が0件。** 管理の不備は、発生の仕組みの下に「なぜ防げなかったか」として書かれていれば可 (c) 設備投資を伴う対策は、評価で×の足切りに落ちているか、根拠（予算・期間）付きで残っている (d) 原因と対策を確かめた出所（調べた資料）が記録されている | 中骨に「校正周期が長い」とだけ書く。小さな不良に設備の増設を主対策にする |
| R7 | 評価軸を決め打ちする | (a) 評価軸を選んだ理由（案件の制約）が1行以上ある (b) 実現性が工数と難易度に分かれている。分けない場合は理由がある (c) ×が1つでもある案は不採用 (d) しきい値が評価の前に示されている (e) 採用案が真因ごとに1つ以上ある | 「効果・実現性・コスト」を理由なく使う。×のある案が合計点で採用される |
| R8 | 系統図と評価を別々に出す | 系統図と評価列が1枚（1つの表、または1枚のスライド）でつながっている | 系統図とマトリックス図が別スライド |
| R9 | 選ばなかった道具とその理由を資料に載せる | 先方向けの資料に、選ばなかった道具とその理由が0件（利用者への応答に書くのは可） | スライドに「散布図ではなく層別を選んだ理由」 |
| R10 | 道具を何のために使うかが伝わらない | 資料と応答の両方で、各道具の初出に「その道具で何の数値・何の判断が決まるか」が書かれている。全道具について満たす | 「散布図を描きます」とだけ書き、何を決めるかがない |
| R11 | 観点を道具として名乗る | (a) 5W＋1H・4M などの観点を「QC7つ道具」「道具」と名乗った箇所が0件 (b) 実際に使った道具（チェックシートなど）を名乗っている | 「QC7つ道具：5W1H」のバッジ |
| R12 | 次の1手だけ示し、全体像が見えない | 利用者への応答で、区切りごとに「残作業の全体像」と「推奨する次の1手」が両方ある | 次の1手だけ、または全体像だけ |
| R13 | 数値を作りながら決め、途中で組み直す | (a) 資料に入る前に、数値骨格（期間・母数・全体件数・項目別件数・対象と対象外・項目別の削減・目標・到達下限）が1か所にまとめられている (b) その骨格の検算（縦計・率・積み上げ）が通っている (c) 資料の中で同じ数値が食い違う箇所が0件 (d) 数値骨格の表に、月ごとの段と実績が入っている（別の表で持っていない） (e) 資料の率はすべて、骨格の件数÷母数から計算した値と一致する（古い率が残っていない） | スライドを作りながら数値を決め、途中で組み直す |

### 追加規則（R14〜R23）：v1.8 系の実使用で起きた失敗

## 6. 物差し（原因の現実性を判定する）

**スキルには書かない。** 判定のためだけに使う。スキルに書くと、実行する側が物差しを写してしまい、検証にならない。

**使い方**：出た原因を、下の一覧と照らす。一覧の範囲外の原因は、**事例の材料に根拠があれば可**、なければ非現実的と判定する（R6(a)）。

### 事例A：ねじの緩み・はんだ不良

| 不良 | 一般的な原因の範囲 |
|---|---|
| ねじの緩み | 初期緩み（接触面のなじみ）、陥没緩み（座面の塑性変形・へたり）、回転緩み（振動・衝撃）、締付不足（軸力不足）、微小摩耗 |
| はんだ不良 | 加熱不足・温度不足（ぬれ不良、未はんだ）、はんだ量過多（ブリッジ）、部品・パッドの酸化、フラックスの不適、急激な温度上昇（はんだボール）、加熱過多（オーバーヒート） |

校正周期・点検頻度は、この一覧に入っていない（管理の不備であって、ねじの緩み・はんだ不良の発生の仕組みではない）。
中骨にこれだけが置かれていたら R6(b) で不合格。

出所（2026-09-22 確認）：八幡ねじ「ねじのゆるみとその対策」、キーエンス「ねじの緩みと緩み止め」、
アイアール技術者教育研究所「ねじの緩み防止方法」、HAKKO「はんだ付けの失敗例」、
RSコンポーネンツ「はんだ付け不良の原因・対策」

### 事例B：検査工程の見逃し

| 区分 | 一般的な原因の範囲 |
|---|---|
| 生理的 | 疲労、長時間の連続作業による注意力の低下、目の疲れ（ピント調節の低下） |
| 環境的 | 照明の暗さ・不均一・影・反射、騒音、作業台の高さや姿勢の負担 |
| 判定の基準 | 判定基準があいまい（どこからが不良か決まっていない）、限度見本がない・古い、検査員ごとの判定のばらつき、教育の不足 |
| 作業のしかた | 検査速度を重視しすぎる（タクトに追われる） |
| 慣れ | 不良の発生率が低く、良品が続くことで異常に気づかなくなる |

**事例Bでは、判定基準や限度見本の不備が、見逃しの発生の仕組みそのものになる。**
「検査員ごとに判定が分かれる（中骨）← 限度見本がなく、境界の傷を感覚で判定している（小骨）」のように、
見逃しが起きる仕組みの中で書かれていれば R6(b) は合格。

## 8. 不合格・判定不能が出たとき

**判定したセッションで、その場でスキルを直さない。** 次の順で進める。

1. 記録表に、不合格の条件の記号と根拠を書く
2. `docs/feedback.md` に1行足す（日付／依頼の要約／期待した挙動／実際の挙動／推定原因）。
   推定原因には、**どの規則が、どの場面で、なぜ届かなかったか**を書く
3. スキルの改訂は `skill-builder` の `references/60_revise.md` の手順で行う
   （症状の分類 → 原因 → 記録の件数で対症か根治かを決める → 提案して承認 → 直して検証）
4. 直したら、**同じ実行を同じ基準でやり直す。** 基準は変えない
