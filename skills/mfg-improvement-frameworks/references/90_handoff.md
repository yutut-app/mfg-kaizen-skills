**道具と道具の継ぎ目だけを集めたファイル。** 各道具の使い方は `30_qc7.md` `40_n7.md` にある。
ここに書くのは、**ある道具の出力が次の道具の入力になるときの変換規則**。

**間違いはほぼ全てここで起きる。** 図表を2つ以上またぐ作業では必ずこのファイルを読む。

## 1. 受け渡しの全体表

**各ステップの末尾に「この道具で得たもの」「次にやること」を必ず書く。**
報告資料でも教育資料でも、ここが書けないステップは実質的に飛ばしている。

### 受け渡しは型ではなく「前のステップの出力物」で決まる

**型で引かない。** 型で引くと、複合した案件でどちらの行を引くか決まらなくなる。
引くのは「**直前のステップが実際に何を出力したか**」。

```
直前のステップの出力物 ─→ 変換規則 ─→ 次の道具の入力
        ↑
   これだけが継ぎ目を決める。主たる型が何かは関係しない
```

この原則により、複合した案件でも**借りたステップは借りた型の行を引くだけ**で済む
（第1章の「複合するときの引き方」）。

### 問題解決型（代表的な並び）

| # | ステップ | この道具で得たもの | 次への入力になる形 |
|---|---|---|---|
| 1 | テーマ選定 | 重点対象の項目（パレート図の上位） | ステップ2で測る対象 |
| 2 | 現状把握 | 特性の現状値と層別結果（件数と母数） | ステップ3の目標の起点 |
| 3 | 目標設定 | 特性の裏返し＋数値＋期限 | **系統図の最上位の目的** |
| 4 | 活動計画 | 担当・期限・順序 | 実施の管理単位 |
| 5 | 要因解析 | **検証で残した真因**（外した候補とその理由を含む） | 系統図の1次手段の元 |
| 6 | 対策立案 | 実行可能な対策案の一覧（系統図の末端） | **マトリックス図の評価対象全件** |
| 6 | 対策選定 | 採用案と不採用案（理由つき） | 実施計画 |
| 7 | 効果確認 | 対策前後の同一指標・同一層別の比較 | 目標との差 |
| 8 | 歯止め | QC工程表・作業標準書への反映箇所 | 日常管理（SDCA） |

### 施策実行型

問題解決型から要因解析を省いた形。**省いた分、受け渡しが1つ減る。**

| ステップ | この道具で得たもの | 次への入力になる形 |
|---|---|---|
| テーマ選定〜活動計画 | 問題解決型と同じ | 同じ |
| （要因解析なし） | **既知の原因**（データの裏付けを確認したもの） | 系統図の1次手段の元 |
| 対策実施 | 対策案の一覧 | マトリックス図の評価対象全件 |
| 効果確認・標準化 | 問題解決型と同じ | 同じ |

**「原因は既知」の根拠を必ず記録に残す。** 裏付けがないまま系統図に渡すと、
要因解析を飛ばした事実が資料から消え、後で検証できなくなる。

### 課題達成型

**真因が存在しない。** 系統図の1次手段は真因の裏返しではなく、攻め所からの方策。

| ステップ | この道具で得たもの | 次への入力になる形 |
|---|---|---|
| テーマ選定 | ありたい姿と現状のギャップ | 攻め所を探す範囲 |
| 攻め所と目標の設定 | **攻め所**（どこを攻めれば届くか）＋数値・期限 | 系統図の目的と1次手段の元 |
| 方策の立案 | 方策の一覧（系統図の末端） | マトリックス図の評価対象全件 |
| 成功シナリオの追究 | 各方策の障害と対処 | 実施計画（PDPCの分岐） |
| 実施・効果確認・標準化 | 問題解決型と同じ | 同じ |

### 未然防止型

**データがない前提。** 数値で絞る継ぎ目が、すべて評価軸で絞る継ぎ目に置き換わる。

| ステップ | この道具で得たもの | 次への入力になる形 |
|---|---|---|
| 想定問題の洗い出し | 起こりうる不具合の一覧（4M × 3H） | 評価の対象 |
| 重要度の評価 | **残った想定問題**（影響度・発生頻度・検出しやすさで絞ったもの） | 系統図の1次手段の元 |
| 対策立案 | 予防策と、起きた場合の対処 | マトリックス図の評価対象全件 |
| 歯止め | QC工程表・4M変更管理への登録箇所 | 日常管理 |

**パレート図・管理図・層別による検算はこの型では成立しない。** 実績データがないため。
代わりに、評価軸の点数と選定理由を記録して再現性を担保する。

### 型が複合するとき

`10_qc-story.md` 第6章のとおり、1案件が1つの型に収まることは実務ではまれ。
**主たる型を1つ決め、必要な箇所だけ他の型から借りる。**

#### 複合するときの引き方

```
1. 主たる型の表を骨格に使う
2. 借りたステップは、借りた型の行を引く
3. 借りた箇所の「前後」が新しい継ぎ目になる。ここが最も事故が多い
```

**表を引き直すのは借りたステップだけ。** 他は主たる型のまま。
出力物で引く原則（第1章冒頭）があるため、これで矛盾は起きない。

#### 複合パターン別の継ぎ目

`10_qc-story.md` 第6章の5パターンに対応する。

| 複合パターン | 新しくできる継ぎ目 | 渡し方 |
|---|---|---|
| 復帰と引き上げ（問題解決型＋課題達成型の目標設定） | 目標 → 系統図 | 目標を**2本に分ける**（復帰分・上乗せ分）。検算も2本。1本にまとめると、どちらが未達か分からなくなる |
| 原因が一部既知（問題解決型＋施策実行型） | 要因解析 → 系統図 | 既知分は施策実行型の行、未知分は問題解決型の行。**1枚の系統図に混ぜず、1次手段に出所の列を付ける** |
| 対策が効かず再発（問題解決型＋未然防止型の標準化） | 効果確認 → 歯止め | 歯止めに 4M × 3H を足す。効果確認の結果を、次の変化点の洗い出しの入力にする |
| 新工程＋類似工程の実績（未然防止型＋問題解決型の現状把握） | 流用データ → リスク評価 | **流用元と適用範囲を明記する。** 母数が違うので率をそのまま持ち込まない |
| 実行段階で新不良（施策実行型＋問題解決型の要因解析） | 挿入した要因解析 → 系統図 | 新規事象は**別の系統図を立てる。** 既存の系統図に追記すると、当初の対策と新規対策の区別が消える |

#### 段階に分けたときの継ぎ目

復帰と引き上げのように段階に分ける場合（`10_qc-story.md` 第6章）、
**段階と段階の間そのものが継ぎ目になる。**

```
第1段階（問題解決型）の効果確認 ─→ 第2段階（課題達成型）のテーマ選定・攻め所
```

| 渡すもの | 注意 |
|---|---|
| 到達水準 | **第1段階の目標値ではなく実績値**を第2段階の起点にする |
| 管理線 | 第1段階の対策後データで引き直してから渡す（第7章） |
| 母数・期間 | 段階ごとに違う。1枚の資料にまとめるときは列を分ける |

#### 混在の事故ポイント

複合で最も多い失敗は、**出所の違うものを1枚にまとめること。**

| 症状 | 何が混ざったか | 対処 |
|---|---|---|
| 1枚の系統図に、由来の違う1次手段が並ぶ | 真因由来／攻め所由来／既知原因由来 | 1次手段に出所の列を付けるか、図を分ける |
| 絞り込み回数が箇所によって違うのに評価表が1枚 | 1回目を経た案と経ていない案 | 評価表に「1回目の根拠」列を足す |
| 前後比較の母数が合わない | 段階・期間の違うデータ | 段階ごとに列を分ける |

### 用語は使う前に定義する

後のステップで説明する用語を、前のステップで使わない。
「真因」「管理限界」「主要因」は、**初出の箇所で1行の定義を添える。**
定義なしに使った語は、読み手の中で別の意味に置き換わる。

## 2. 特性要因図 → 系統図

**最も間違えやすい継ぎ目。** 以下を守る。

### 階層は対応しない

```
特性要因図                        系統図
─────────────────                ─────────────────
特性（右端）                 ✗→   目的
大骨（4M）                   ✗→   1次手段
中骨                         ✗→   2次手段
小骨                              3次手段
```

**この対応は誤り。** 正しくは次のとおり。

```
系統図の目的      ← その時点の目標（特性の裏返し ＋ 数値 ＋ 期限）
系統図の1次手段   ← 直前のステップで残ったものを裏返して動詞化したもの
系統図の2次以降   ← その手段を実行可能なレベルまで展開したもの
```

**「直前のステップで残ったもの」は型によって違う。** 型で引かず、出力物で引く（第1章）。

| 直前のステップの出力物 | どの型か | 1次手段の作り方 |
|---|---|---|
| データで残した末端の真因 | 問題解決型 | 裏返して動詞化する |
| 裏付けを確認した既知の原因 | 施策実行型 | 裏返して動詞化する（同じ） |
| **攻め所** | 課題達成型 | 裏返さない。攻め所を達成する方策として展開する |
| 評価で残した想定問題 | 未然防止型 | 裏返して動詞化する（「〜が起きない」） |

**課題達成型だけ裏返しではない。** 問題が起きていないので裏返す対象がない。
「攻め所＝加工時間の短縮」なら、1次手段は「加工時間を短縮する手段」を展開する。

**大骨（4M）は系統図に持ち込まない。** 4Mは要因を分類するための切り口であって、
手段ではない。「Manを改善する」という手段は存在しない。

中骨も原則として持ち込まない。データで残ったのが末端（小骨）なら、
1次手段になるのはその末端であって、その親ではない。

### 語の変換：名詞・状態 → 動詞・行動

要因は**名詞または状態**で書かれている。手段は**動詞または行動**で書く。
裏返して動詞化する。

**元の語は残す。** 言い換えると、どの要因に対する手段かの追跡ができなくなる。

| 末端の真因（名詞・状態） | 1次手段（動詞・行動） | 判定 |
|---|---|---|
| 切込み量の設定が号機で違う | 切込み量の設定を号機で違わせない | 可。元の語（切込み量・設定）が残っている |
| 切込み量の設定が号機で違う | 設備条件を標準化する | 不可。「切込み量」が消え、追跡が切れる |
| 治具の位置決めピンが摩耗する | 位置決めピンを摩耗させない | 可 |
| 治具の位置決めピンが摩耗する | 設備の保全を強化する | 不可。抽象化されている |
| ガンとワークの距離を目測で合わせている | 距離を目測で合わせさせない | 可 |

**否定形で止めてよい。** 「〜しない」「〜させない」は1次手段として正しい形で、
具体的な打ち手は2次以降で展開する。1次手段の段階で解決策を書き込むと、
展開が1段で終わり、いつもの対策しか出てこない。

### 絞り込んだ要因だけを展開する

**データで否定した要因には系統図を展開しない。**
展開すると、否定したはずの要因への対策が対策一覧に混ざり、
ステップ5の絞り込みが無意味になる。

出典：日科技連「新QC七つ道具の活用ポイント 第4回」（系統図は絞り込んだ主要因に対して展開する）

落とした要因は系統図には出さず、**ステップ5の記録（第4章の様式）に残す。**

## 3. 絞り込みは2回ある

**対象が違う。** 混同すると「主要因への対策だから評価不要」「案が出た時点で即採用」
という誤りが出る。

| | 1回目 | 2回目 |
|---|---|---|
| 絞る対象 | **要因・攻め所・想定問題**（何を攻めるか） | **手段（対策案・方策）** |
| 絞る根拠 | 型による（下表） | 評価軸（案件ごとに選ぶ。`40_n7.md` マトリックス図） |
| 使う道具 | 型による（下表） | マトリックス図 |
| 出力 | 残ったもの ＋ 落としたものと理由 | 採用案 ＋ 不採用案と理由 |
| 飛ばすと | 効かない対策を立てる | 実行されない対策が並ぶ |

### 1回目は型によって変わる。2回目はどの型でも必ずある

| 型 | 1回目（何を・何で絞るか） | 2回目 |
|---|---|---|
| 問題解決型 | 要因を**データ**で絞る（層別・散布図） | 手段を評価軸で絞る |
| 施策実行型 | **なし。** 原因が既知のため（裏付けの確認だけ行う） | 手段を評価軸で絞る |
| 課題達成型 | 攻め所を**評価軸**で絞る（マトリックス図） | 方策を評価軸で絞る |
| 未然防止型 | 想定問題を**リスク評価**で絞る（影響度・発生頻度・検出しやすさ） | 対策を評価軸で絞る |

**2回目はどの型でも免除されない。** 1回目を通ったことも、原因が既知であることも、
2回目を省く理由にならない。効果・実現性・コストは案ごとに違う。

**1回目と2回目で評価軸が同じになる型（課題達成型）では、軸を使い分ける。**
1回目は目標への寄与で絞り、2回目は実行可能性で絞る。同じ軸を2回使うと、
2回目が1回目の追認になって機能しない。

## 4. 絞り込みの単位は末端の要因

### 候補と真因を分ける：特性要因図 → 検証 → 真因の確定

**特性要因図が出すのは要因の候補であって、真因ではない。**
真因と呼んでよいのは、層別・散布図などで検証して残した後だけ。

```
特性要因図       要因の候補を出す（この段階では全部が候補）
   ↓
検証             候補ごとに、層別・散布図・追加のデータ取りで効いているかを確かめる
   ↓             （現状把握の2回目。`10_qc-story.md` ステップ2）
真因の確定       残った候補を真因と呼ぶ。外した候補は理由とともに残す
```

| やってはいけないこと | 何が起きるか |
|---|---|
| 特性要因図の中で真因を先に決める（赤字・丸印で強調する） | 検証が「決めた真因を裏付ける作業」になり、結論ありきに見える |
| 外した候補を記録から消す | 対策が空振りしたときに戻る先がない。検証したことも伝わらない |
| 検証した候補が全部「当たり」 | 検証の設計を疑う。当たりそうな候補だけを選んで確かめていないか見直す |

### 4Mは絞り込みの対象ではない

4M（大骨）は**分類の切り口**。「Machineは関係ない」という形で大骨ごと落とさない。
落とすのは**末端の要因1つずつ**。

**同じ大骨の中に、残る要因と落ちる要因が混在するのが正常。**
大骨単位できれいに残る／落ちるのは、末端まで見ていない証拠。

### 落とした理由を残す

採用理由より、**落とした理由の方が再現性に効く。**
同じ調査を次回繰り返さずに済み、対策が空振りしたときにどこへ戻るかが分かる。

| 大骨 | 要因の候補 | 検証の結果 | 根拠 |
|---|---|---|---|
| Machine | ノズルに塗料が固着する | 残す（真因） | 平面部14件を号機別に層別。2号機 12件/1250個（0.96%）、1号機 2件/1250個（0.16%）。2号機のノズルに固着を確認 |
| Machine | エア配管を他設備と共用している | 外す | 霧化エア圧の実測値と平面部の不良に相関なし（散布図 n=52） |
| Man | 距離を目測で合わせている | 残す（真因） | 端部26件を作業者別に層別。目測している3名 21件/900個（2.3%）、他5名 5件/1600個（0.31%） |
| Man | 折り返しで速度が落ちて重なる | 外す | ガン移動速度の実測値と端部の不良に相関なし（散布図 n=40）。層別で見えた作業者差を説明できない |

見本の題材は塗装ムラ（`80_examples.md` 付録と同じ数値骨格）。**見本は一例で、利用者の案件の原因の候補ではない。**

**「層別で見えた条件差を説明できない」は正当な落とす理由。**
逆に「関係なさそう」「優先度が低い」は理由にならない。

## 5. 系統図 → マトリックス図

**評価対象は、系統図で出た対策案のすべて。**
「主要因への対策だから評価は不要」は誤り。系統図の末端に並んだ案は全件が評価対象。

| 系統図の出力 | マトリックス図での扱い |
|---|---|
| 末端の対策案 | 行に置く。**全件** |
| 途中の中間手段 | 行に置かない（実行できないため） |
| 評価軸 | 列に置く。候補から案件ごとに選ぶ（`40_n7.md` マトリックス図） |

評価記号・総合評価列の作法は `40_n7.md` のマトリックス図法を読む。

## 6. パレート図 → テーマ・目標

**この章は実績データがある型でのみ成立する。**（問題解決型・施策実行型、
および類似工程のデータを流用する場合）

未然防止型・データのない課題達成型では、パレート図を描けない。
代わりにリスク評価マトリックス（影響度・発生頻度・検出しやすさ）で対象を絞り、
**選定理由を記録して再現性を担保する**（第1章の未然防止型の表）。

### 項目数は目標から逆算する

**テーマは上位1項目とは限らない。** 先に「上位N項目」と決めてから目標を置くのではなく、
**目標に届くかで項目数を決める。**

```
目標値を置く
   ↓
上位1項目を全部なくしたら目標に届くか
   ├─ 届く  → テーマは上位1項目
   └─ 届かない → 2番目を足す。それでも届かなければ3番目
```

届かないまま上位1項目に絞ると、**対策が全部成功しても目標未達**になる。
この検算を必ず行う（第7章）。

### 語る順を固定する

**目標を先に言い、そこから必要な項目数を導く。** 順序が逆だと、
「上位2項目が必要」と言いながら1項目しか追わない、という矛盾が出る。

| 順 | 語ること | 出す数字 |
|---|---|---|
| 1 | **目標** | 現状値 → 目標値（いつまでに） |
| 2 | **必要削減量** | 目標を達成するには何件減らす必要があるか |
| 3 | **累積でどこまで要るか** | 上位から累積して、必要削減量に届く項目数 |
| 4 | **各項目をどこまで減らせるか** | 要因ごとの見込みを積み上げ、必要削減量に届くことを示す（`10_qc-story.md` ステップ3） |

```
現状 45件 → 目標 17件（四半期あたり）              … 1 目標
必要削減量 28件                                    … 2 必要削減量
上位1項目 26件では届かない
上位2項目 26+14=40件 ≥ 28                          … 3 累積で2項目必要
項目A 26→8件（69%減）、項目B 14→4件（71%減）      … 4 各項目の削減（要因ごとの積み上げ）
```

**3で出した項目数を、以降のステップで最後まで追う。**
2項目必要と出したなら、要因解析も対策も効果確認も2項目分やる。
1項目に絞るなら、目標を見直すか、絞る理由を書く（`10_qc-story.md` 第7章）。

### 二段階で使う

1段目で不良項目を選び、**2段目でその項目の中身を層別してさらに絞る。**

```
1段目：不良項目別のパレート図  → 「寸法不良」が最大
   ↓
2段目：寸法不良を層別（号機別・時間帯別・機種別）→ 2号機の段取り直後に集中
   ↓
テーマ：2号機の段取り直後の寸法不良を減らす
```

1段目で止めると、テーマが「寸法不良を減らす」のままになり、
以降のステップで何を測ればよいか決まらない。

## 7. 目標 → 効果確認 → 管理図

**検算の式は数値目標がある型でのみ成立する。**
未然防止型では実績がないため、効果確認は「想定問題が発生しなかったこと」と
「歯止めが運用されていること」の確認になる。数値の検算は対象外。

### 部分と全体を式でつなぐ

**部分の削減件数と、全体の率の改善が計算で一致すること。**
「対象2項目 40件→12件」と「全体 1.8%→0.68%」が式でつながっているかを、必ず検算する。

```
検算の形
  現状の全体率 = 全体の不良件数 ÷ 母数
  目標の全体率 = (全体の不良件数 − 対象項目の削減件数) ÷ 母数
```

つながらない場合は、目標値か削減件数のどちらかが根拠なく置かれている。

### 対象外を明示する

「乾燥条件・その他の5件は今回は触らない」と書く。書かないと、
全体率の目標が達成不能な水準に置かれていても気づけない。

### ゼロを目標にしない理由を数字で示す

対象項目を**全部なくしても到達しない水準**がある。
その場合、ゼロは目標として成立しない。到達可能な下限を計算で示す。

```
対象項目を全て0にしたときの全体率 = (全体件数 − 対象項目件数) ÷ 母数
  → この値が「今回の活動で到達しうる下限」
```

### 効果確認で見る側

管理図で改善を確認するときに見るのは**下側（LCL）**。
上振れを検出する UCL は主役ではない。詳細は `30_qc7.md` の管理図。

## 8. 受け渡しが切れているときの症状

| 症状 | 切れている継ぎ目 | 戻る先 |
|---|---|---|
| 系統図の1次手段に「Man」「Machine」が並ぶ | 特性要因図 → 系統図 | 第2章 |
| 対策一覧に、データで否定した要因への対策がある | 要因の絞り込み → 系統図 | 第2章 |
| 手段が名詞で書かれている | 語の変換 | 第2章 |
| 対策案がそのまま採用され、評価表がない | 2回目の絞り込み | 第3章・第5章 |
| 大骨ごと残す／落とすで判定している | 絞り込みの単位 | 第4章 |
| 落とした要因の理由が残っていない | ステップ5の記録 | 第4章 |
| 対策が全部成功しても目標に届かない | パレート図 → 目標 | 第6章 |
| 目標の率と件数が式でつながらない | 目標設定の検算 | 第7章 |
| テーマが「不良を減らす」のまま | パレート図の二段階適用 | 第6章 |
| 課題達成型なのに「真因」を探している | 型と出力物の取り違え | 第1章・第2章 |
| 1枚の系統図に由来の違う1次手段が並ぶ | 複合時の混在 | 第1章「混在の事故ポイント」 |
| 第2段階の起点が第1段階の目標値になっている | 段階間の受け渡し | 第1章「段階に分けたときの継ぎ目」 |
| 未然防止型なのに管理図で効果確認しようとした | データのない型への数値ルールの適用 | 第6章・第7章の冒頭 |

## 9. 数値の連鎖

**1枚の数字を変えると、後続の複数枚が同時に崩れる。**
検算は1枚ごとに行うだけでは足りない。**どこに波及するかを先に知っておく。**

### 数値骨格を先に固定する

**資料や事例を作るときは、各スライドに入る前に数値骨格を1枚にまとめて固定し、検算する。**
スライドを作りながら数値を決めると、後で1つ変えたときに複数枚を組み直すことになる。

骨格に入れるもの（すべて件数と母数で。率は骨格から計算して出す）。

| 項目 | 例（塗装ムラ） |
|---|---|
| 対象期間と母数 | 6〜8月、2,500個 |
| 全体の不良件数と率 | 45件（1.8%） |
| 項目別の件数（縦計が全体と一致） | 端部26 / 平面部14 / 穴周り3 / その他2 = 45 |
| 対象にする項目と、対象外にする項目 | 対象 26+14=40、対象外 3+2=5 |
| 項目別の削減見込み（要因ごとに見積もって積み上げる） | 端部26→8、平面部14→4 |
| 目標（件数と率） | 17件（0.68%） |
| 到達下限（対象を全て0にした場合） | 5件（0.2%） |

**骨格の検算が通るまで、スライドに入らない。** 検算の順序は下の「検算の順序」。

### 波及の依存表

左の数字を変えたら、右の全部を必ず作り直す。

| 変えた数字 | 波及する先 |
|---|---|
| **母数**（生産数・検査数） | 全ステップの率、パレート図の縦軸、管理図の管理限界、目標の率、効果確認の前後比較 |
| **対象期間** | 件数、母数、パレート図、前後比較の期間長、管理図の群 |
| **不良モードの定義** | パレート図の分類、層別表、特性要因図の特性、目標、効果確認の分類 |
| **パレート図の項目数** | 目標の必要削減量、要因解析の対象、対策の数、効果確認の対象 |
| **目標値** | 必要削減量、各項目の必要削減率、項目数（足りなければ増える）、効果確認の判定 |
| **層別の区切り方** | 層別表の全行、要因の絞り込み結果、残す要因、系統図の1次手段 |
| **残す／落とす要因の判定** | 系統図の枝、対策案の数、マトリックス図の行、実施計画 |
| **対策後のデータ** | 効果確認の図、管理線の引き直し、歯止めの管理値 |

### 検算の順序

**上流から下流へ1方向に検算する。** 下流から直すと、上流と食い違ったまま辻褄が合う。

```
母数・期間・定義  →  件数・率  →  パレート図  →  目標  →  要因の絞り込み
      →  対策案  →  効果確認  →  管理値
```

### 資料を直すときの手順

1. **変えた数字を1つ特定する**
2. 上の依存表で**波及先を全部列挙する**
3. 波及先を**上流から順に**作り直す
4. **最後に全体の縦計と率を再検算する**（`SKILL.md` 出力の作法9）

**1枚だけ直して差し替えない。** 差し替えた1枚は正しく見えるので、
食い違いに気づけない。これは `60_revise.md` が「直した本人には見えない」と
呼ぶ型の事故と同じ構造。
