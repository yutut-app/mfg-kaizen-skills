## 1. この表の使い方

順に判定する。**飛ばさない。**

```
Step 0  入力形式を判定           → 第3章
Step 1  型を選ぶ                 → 第4章
Step 2  今どのステップかを特定    → 第5章
Step 3  そのステップの道具を選ぶ  → 第5章
Step 4  分解軸を掛け合わせる      → 第6章
```

利用者が道具を名指ししている場合（「特性要因図を書きたい」など）は Step 0 と Step 4 のみ行い、
残りは飛ばしてよい。ただし**入力形式の判定は必ず行う**。データがないまま定量の道具に進むと必ず行き詰まる。

参照先ファイル：
`10_qc-story.md` / `20_factor-axes.md` / `30_qc7.md` / `40_n7.md` / `50_standardization.md` / `60_data-design.md`

**具体的な進め方が必要なときは `70_cases.md` を読む。** 判断の過程が時系列で書かれている。
**図表の書式に迷ったら `80_examples.md` を読む。** 記入済みの見本がある。

## 2. 道具のつながり

QC7つ道具と新QC7つ道具は**切り離されたものではない。**
QCストーリーの8ステップ（第5章）の上に、両方が交互に並んでいる。

### 発散と収束

要因や対策を**出す**のが発散、**整理して絞る**のが収束。
KJ法（＝親和図法）の説明で使われる考え方で、**この往復が改善活動の本体**になる。

**1つの道具の中でも両方が起きる。** 道具ごとに発散か収束かが決まっているのではない。

| 道具 | 発散の部分 | 収束の部分 |
|---|---|---|
| 特性要因図 | 要因を思いつくまま出す | 4Mの大骨に分類し、疑わしいものに絞る |
| 親和図 | カードを書き出す（ブレーンストーミング） | 似たものを集めて見出しを付ける |
| 連関図 | 要因を出す | 矢印をたどって影響の大きいものを特定する |
| 系統図 | 手段を広げる（5Eで視野を広げる） | 実行できるものに絞る |
| パレート図 | — | 重点対象に絞る |
| 層別・散布図 | — | 仮説を1つずつ潰す |

**カードやアイデアを出す作業（ブレーンストーミング）は、これらの道具の手順の一部。**
単独では使わず、必ず次の道具とセットになる。

### 発散が足りないと起きること

- 特性要因図に一般論しか並ばない（現場の人が出していない）
- 対策が「教育を徹底する」だけになる（系統図の展開が浅い）
- 親和図がいつもの分類に戻る（カードが少ない）

### 収束が足りないと起きること

- 要因を挙げただけで対策に進む（データで確かめていない）
- 対策案が多すぎて実行されない（評価軸で絞っていない）

### 言語データと数値データが交互に現れる

| ステップ | 扱うデータ | 主な道具 |
|---|---|---|
| 1 テーマ選定 | 数値／言語 | パレート図、親和図 |
| 2 現状把握 | 数値 | チェックシート、層別、ヒストグラム、管理図 |
| 3 目標設定 | 数値 | グラフ、マトリックス図 |
| 4 活動計画 | 言語 | アローダイアグラム |
| 5 要因解析 | 言語 → 数値 | 特性要因図・連関図で洗い出し、層別・散布図で検証 |
| 6 対策立案・実施 | 言語 | 系統図、マトリックス図、PDPC、ECRS |
| 7 効果確認 | 数値 | パレート図、管理図、ヒストグラム |
| 8 歯止め（標準化） | 両方 | QC工程表、作業標準書、4M変更管理、管理図 |

**新QC7は言語データ、QC7は数値データを扱う。** 実務ではこの違いの方が重要。
発散か収束かで道具を選ぶのではなく、**手元にあるデータの種類で選ぶ。**

**言葉で構造を作り、数値で確かめる。** 片方だけでは回らない。
言葉だけでは思い込みのまま進み、数値だけでは何を測るべきかが決まらない。

### ステップの飛ばし方

順に全部やる必要はない。

| 状況 | 飛ばせるステップ |
|---|---|
| 層別キーの揃ったデータが最初からある | 5 要因解析の前半（層別で事実を先に見る方が速い） |
| 原因がすでに分かっている（施策実行型） | 5 要因解析 |
| データがない | 2 現状把握・7 効果確認は数値で行えない。言語データの道具で進める |

**8 歯止め（標準化）は飛ばせない。** ここを飛ばすと再発する。

## 3. 入力形式の判定

| 入力 | 初動 | 進む先 |
|---|---|---|
| Excel / CSV | 読み込み、列構成と件数を確認。層別できるキー（日付・ライン・作業者・機種・ロット）の有無を見る | 定量の道具（第4章） |
| 帳票・PDF | 抽出し、表として構造化できるか判定 | 可 → 定量／不可 → 言語データ扱い |
| 口頭・手入力 | 言語データとして扱う。定量的な結論が必要なら取得設計を挟む | 定性の道具（第4章） |
| データがない | **定量の道具に進まない。** 取得設計を先に行う | `60_data-design.md` |

### 判定の要点

- 「データはある」と言われても、**層別キーがなければ層別できない**。列を確認してから道具を決める。
- 件数が30未満のときはヒストグラムも管理図も意味を持たない。件数を先に確認する。
- 「データがない」ケースで最もやってはいけないのは、推測値でグラフを作ること。取得設計に切り替える。

## 4. 型の選定

3問で決まる。詳細は `10_qc-story.md`、実例は `70_cases.md`。

**選ぶのは「主たる型」1つ。排他ではない。** 1案件が1つの型に収まることは実務では
まれで、主たる骨格を決めたうえで必要な部分を他の型から借りる。
複合パターンと段階分割の判断は `10_qc-story.md` 第6章。

| 問い | Yes | No |
|---|---|---|
| Q1. まだ起きていないリスクへの備えか | **未然防止型** | Q2へ |
| Q2. 現状復帰ではなく、今より上の水準を目指すか | **課題達成型** | Q3へ |
| Q3. 原因はすでに分かっているか | **施策実行型** | **問題解決型** |

### 型による違い

| 型 | 骨格 | 特徴 |
|---|---|---|
| 問題解決型 | 8ステップ（第4章の表） | 最も標準的。要因解析を含む |
| 施策実行型 | 問題解決型から**要因解析を省略** | 原因が既知。対策の実行が主 |
| 課題達成型 | テーマ選定 → 攻め所と目標 → 方策立案 → 成功シナリオ追究 → 実施 → 効果確認 → 標準化 | 現状把握・要因解析の代わりに方策立案が中心 |
| 未然防止型 | 想定問題の洗い出し → 評価 → 対策 → 歯止め | 起きていない事象を扱う。データがないのが前提 |

**誤選定が最も多いのは問題解決型と課題達成型の取り違え。**
「不良を減らしたい」は問題解決型だが、「不良ゼロを実現したい」は課題達成型になりうる。
現状の基準値に戻すのか、基準そのものを上げるのかを利用者に確認する。

**両方を求められた場合は段階に分ける。** 課題達成型には要因解析のステップがないため、
悪化分は課題達成型では拾えない。第1段階で問題解決型により復帰させ、
第2段階で課題達成型により引き上げる。

**利用者には主たる型だけを伝える。** 「複合で進めます」では現場が動けない。
借りる箇所だけを具体的に示す。

## 5. ステップ × 道具

問題解決型の8ステップを基準に示す。他の型は第3章の骨格に読み替える。

| # | ステップ | 主に使う道具 | 掛ける分解軸 | 詳細 |
|---|---|---|---|---|
| 1 | テーマ選定 | パレート図、グラフ、親和図 | QCD | `30_qc7.md` `40_n7.md` |
| 2 | 現状把握 | チェックシート、層別、ヒストグラム、管理図、グラフ | 4M / 5M＋1E | `30_qc7.md` `60_data-design.md` |
| 3 | 目標設定 | グラフ、マトリックス図 | QCD | `30_qc7.md` `40_n7.md` |
| 4 | 活動計画 | アローダイアグラム | — | `40_n7.md` |
| 5 | 要因解析 | 特性要因図、連関図、散布図、層別、なぜなぜ分析 | **4M / 安全4M / 3H** | `30_qc7.md` `40_n7.md` `50_standardization.md` |
| 6 | 対策立案・実施 | 系統図、マトリックス図、PDPC、ECRS | 5E | `40_n7.md` `50_standardization.md` |
| 7 | 効果確認 | パレート図（前後比較）、管理図、ヒストグラム、グラフ | QCD | `30_qc7.md` |
| 8 | 歯止め（標準化） | QC工程表、作業標準書、4M変更管理 | 4M | `50_standardization.md` |

### ステップ内での道具の選び分け

**ステップ2（現状把握）**

| 知りたいこと | 道具 |
|---|---|
| どこに集中しているか | パレート図 |
| ばらつきの形 | ヒストグラム |
| 時間的な変化・異常の有無 | 管理図、折れ線グラフ |
| 条件による差 | 層別（＋上記のいずれか） |
| そもそも記録がない | チェックシート設計 |

**ステップ5（要因解析）**

| 状況 | 道具 |
|---|---|
| 要因を網羅的に洗い出す | 特性要因図（大骨に4M） |
| 要因同士が絡み合っている | 連関図 |
| 2つの量の関係を確かめる | 散布図 |
| 特定の要因を深掘りする | なぜなぜ分析 |
| 条件差が原因かを確かめる | 層別 |

**特性要因図と連関図の使い分け**が最も迷いやすい。
要因が階層構造で整理できるなら特性要因図、要因が相互に影響し合って循環しているなら連関図。

**ステップ6（対策立案）**

| 状況 | 道具 |
|---|---|
| 目的から手段へ展開する | 系統図 |
| 複数案を評価軸で比べる | マトリックス図 |
| 障害が予想され迂回路が要る | PDPC |
| 作業そのものを見直す | ECRS |

## 6. 分解軸 × 道具（掛け算）

**このスキルの価値の中心。** 道具は「枠」であり、分解軸は「枠に入れる観点」。
道具だけ使って観点を入れないと、抜け漏れのある分析になる。

| 道具 | 掛ける分解軸 | 具体的な使い方 |
|---|---|---|
| 特性要因図 | 4M（5M＋1E / 6M） | **大骨に4Mを置く。** 中骨・小骨を掘り下げる |
| 特性要因図（安全・ヒューマンエラー） | 安全工学の4M | 大骨を Man / Machine / Media / Management にする |
| 層別 | 4M | 層別キーを 作業者・設備・材料ロット・作業方法 から選ぶ |
| チェックシート | 4M（5M＋1E） | 記録項目に4Mの各要素を含める。環境要因があれば5M＋1E |
| 連関図 | 4M | 初期カードを4Mの各観点から出す |
| 変化点の洗い出し | **4M × 3H** | 各Mについて「初めて・変更・久しぶり」を当てはめる |
| 対策立案 | 5E | 教育・技術・強化・模範・環境の5観点で対策を検討する |
| テーマ選定・効果確認 | QCD | 品質・コスト・納期のどれに効くかで評価する |

### 分解軸の選び分け

| 状況 | 使う軸 | 詳細 |
|---|---|---|
| 標準（迷ったらこれ） | 4M | `20_factor-axes.md` |
| 温度・湿度・振動などが絡む | 5M＋1E | 同上 |
| 管理体制・リソース配分が絡む | 6M | 同上 |
| ヒューマンエラー・事故・安全 | 安全工学の4M | 同上 |
| 変化点管理・未然防止 | 4M × 3H | 同上 |
| 対策を考える段階 | 5E | 同上 |

## 7. 目的からの逆引き

利用者が道具ではなく目的で語ってきたときに引く。

| 言われたこと | 選ぶ道具 |
|---|---|
| 「どこから手を付けるべきか」 | パレート図 |
| 「原因を整理したい」 | 特性要因図（4M） |
| 「原因が絡み合っていて整理できない」 | 連関図 |
| 「意見がバラバラで論点が見えない」 | 親和図 |
| 「対策の案出しをしたい」 | 系統図 |
| 「どの案を選ぶべきか」 | マトリックス図 |
| 「対策がうまくいかない場合に備えたい」 | PDPC |
| 「スケジュールを引きたい」 | アローダイアグラム |
| 「ばらつきが大きい」 | ヒストグラム、層別 |
| 「工程が安定しているか知りたい」 | 管理図 |
| 「AとBに関係があるか知りたい」 | 散布図 |
| 「何を記録すればいいか分からない」 | チェックシート設計 |
| 「同じ問題が再発する」 | なぜなぜ分析 → 標準化（QC工程表） |
| 「作業を効率化したい」 | ECRS |
| 「人や設備が変わると品質が乱れる」 | 4M変更管理（4M × 3H） |
| 「工程を整理して文書化したい」 | QC工程表 |

## 8. 迷ったときの既定値

判断がつかない場合は以下を採る。**利用者に確認を重ねるより、既定値で進めて修正する方が早い。**

| 迷う点 | 既定値 |
|---|---|
| 型 | 問題解決型（両方に当てはまるときもこちらに倒す） |
| 分解軸 | 4M |
| 要因解析の道具 | 特性要因図（大骨＝4M） |
| 現状把握の道具 | パレート図（層別できるなら層別を先に） |
| 対策立案の道具 | 系統図 |
| データ件数が不明 | 件数を先に確認する（推測で進めない） |

ただし以下は既定値で進めず、**必ず利用者に確認する**。

- 現状復帰か、水準の引き上げか（型の分岐が変わる）
- データがあるか、ないか（進む道筋が根本的に変わる）
- 安全・ヒューマンエラーが絡むか（分解軸が変わる）
