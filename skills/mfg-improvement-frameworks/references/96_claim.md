# 96_claim — 主張と、案件全体の中の位置

**ここが「この資料で何を主張するか」を決める唯一の場所。**
道具の選定も数値の検算も正しいのに使われない資料は、ほぼここが空のまま作られている。

実績（2026-11-04 の客先定例の報告資料）。管理指標264件を率・状況・不明に分けた件数を資料にしたところ、
**「今までの課題や目的を再度見直した方がいい」「点の説明になってます」**と返り、
上司からは**「最初に全体のどの位置か伝えるべき」**と指摘された。
作業の内容は正しく、件数も最後まで食い違わなかった。**足りなかったのは主張と位置だけ。**

試験でも再現している。別セッションで3件走らせたところ、
**資料を作る2件とも「今いる位置はQCストーリーの現状把握」とQCの中の位置を書き、
案件全体（最終ゴール→今のフェーズ→今回）の線を書かなかった**
（`docs/ops/verification-v1.10.md` 手順0、R2・R3・R4 が2事例で不合格）。

## 1. 主張の材料を、先に読む

**主張は入口の表を埋めただけでは出てこない。** 作業の対象（件数・分類）を眺めて書くと、
必ず「何をしたか」の説明になる。材料は別の場所にある。

| 順 | 読むもの | 無いときの扱い |
|---|---|---|
| 1 | **案件の目的と課題**（提案書、キックオフ資料、OP表、依頼のメール） | 利用者に聞く。**推測で書かない** |
| 2 | **直前の数回分の会議資料と議事録**（経緯と、前回までに合意した表現） | 「未確認」と書き、確認する。**過去の言い回しを、定義を確かめずに流用しない** |
| 3 | **上司・利用者の指示**（口頭のメモを含む） | — |
| 4 | 主張を1〜2文で書き、**利用者に確認を取る** | 確認が取れるまで構成に入らない |

**過去の資料を読む順は、新しいものから。** 直前の回で使った言葉と型が、読者にとっての前提になっている。

## 2. 主張と位置の確定表（出力必須）

**資料（スライド・報告書）の骨子を出す前に、この表を埋めて利用者への応答に出す。**
文章で「全体の位置も踏まえて作ります」と書くだけでは、出力に現れない。

```markdown
## 主張と位置（読者: 先方報告 / 用途: 進捗報告）

| 項目 | 内容 | 根拠の出所 |
|---|---|---|
| 最終ゴール | <案件が終わったとき何ができているか> | <資料名・該当箇所／誰の発言・日付> |
| 今のフェーズ | <全体の何段目か。前後に何があるか> | 〃 |
| 今回の位置 | <そのフェーズの中のどこか> | 〃 |
| **今回の主張（1〜2文）** | <この資料で読者に何が分かる状態になるか> | 〃 |
| 今回やらないこと | <今回の範囲外。「これから」「最終」に回すもの> | 〃 |
```

### この表の読み方

- **主張は「読者が何が分かる状態になるか」で書く。** 自分が何をしたかではない
  - 悪い：管理指標264件を率・状況・不明に分類した
  - 良い：**今すぐ使える指標が72件あり、それで現場の管理を始められることが分かる**
- **根拠の出所が空の行を残さない。** 空なら「未確認」と書き、利用者に聞く。
  出所の無い主張は、確かめていない仮説と同じ
- **最終ゴール→今のフェーズ→今回の位置は、冒頭1枚で線としてつなぐ。**
  各枚の中でも、どこの話かが分かるようにする
- **QCストーリーの中の位置（ステップ2、要因解析など）は、案件の位置ではない。**
  読者は案件の進み具合を知りたい。ステップ名は手法の話で、`95_audience.md` の仕分けでは
  先方報告に載せない側にある
- **「今回やらないこと」を必ず書く。** 書かないと、次回以降に決めることを先に約束した形になる

### 進み具合を断定するときの出所

**「済み」「完了」「途中」は、確認済みの記録か、利用者の言葉からだけ書く。**
過去の作業報告を、全体の状態と読み替えない。

実績：利用者は「今は管理指標をやっている段階」と言ったのに、資料には「現状把握は済み」「次はガント」と書き、
**「済みではない。全体業務の把握が全体像で、今は管理指標を行っている。ガントは最終」**と返った。
試験でも、利用者が「今は棚卸しをやっている段階」と言った入力に対して、
出力の1枚目が「棚卸しを**完了**」になった（手順0、E1 の R6）。

**段階の定義（何をもって済みとするか）を先に確認する。** 定義が無いまま断定すると、
読者の持っている定義とずれる。

## 3. 止まる条件は「分からないとき」

**「途中の判断は止めない」は、「分かりきっていることは止めない」という意味。**
分からないときは、途中の判断でも止めて聞く。回数で決めない。

| 状況 | 扱い |
|---|---|
| 材料に書いてある。業界で決まりきっている。前例がある | **止めない。** 決めて、何を根拠に決めたかを1行書く |
| **解釈が2つ以上ある。材料に無い。前提が確かめられない** | **止めて聞く。** 途中の判断でも止める |
| 間違えると後続すべてが作り直しになる（主張・読者・用途・型） | **止めて聞く** |

- **既定は「分からないなら止める」**
- 止まるときは、**その時点で未決のものを全部まとめて出す。** 1件ずつ往復しない
- 各問いに「**間違えると何が起きるか**」を添える。無いと利用者は優先順位を判断できない
- 止めずに決めたとき、**根拠が1行書けないなら、それは分かっていない。** 戻って聞く
