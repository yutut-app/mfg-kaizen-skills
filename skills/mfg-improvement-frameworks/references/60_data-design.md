## 1. いつ使うか

| 状況 | 対応 |
|---|---|
| データがない | **本ファイルを使う。** 定量の道具には進まない |
| データはあるが層別キーがない | 本ファイルで層別設計を行い、追加取得する |
| データはあるが件数が足りない | 追加取得の計画を立てる |
| 口頭の情報しかない | 言語データとして `40_n7.md` を使いつつ、並行して取得設計する |

**「データがない」と分かった時点で、推測値でグラフを作らない。** 誤った判断を招く。

## 2. 設計の5項目

記録を始める前に、この5つを決める。

| # | 項目 | 決めること | 決めないとどうなるか |
|---|---|---|---|
| 1 | **何を** | 測る対象（品質特性・管理特性） | 集めた後で「知りたいことが分からない」 |
| 2 | **どの単位で** | 個・ロット・時間・日 | 集計できない |
| 3 | **誰が** | 記録の担当者 | 記録が続かない |
| 4 | **いつ** | 頻度・タイミング | 偏った期間のデータになる |
| 5 | **層別キー** | 一緒に記録する条件 | **後から層別できない** |

**5番目が最重要。** 層別キーは記録時にしか取れない。後から遡って付けることはできない。

### 「何を」の決め方

QCストーリーのステップ3（目標設定）と対応させる。

| 目標 | 測るもの |
|---|---|
| 不良率を下げる | 不良件数、生産数、不良項目の分類 |
| 寸法のばらつきを抑える | 実測寸法（合否ではなく数値） |
| リードタイムを短縮する | 各工程の開始・終了時刻 |

**合否だけを記録すると、ばらつきが見えない。** 可能なら数値を記録する。

## 3. 層別設計

後の分析で「差が出るか」を見たい条件を、記録項目に含める。

### 標準の層別キー（4Mから選ぶ）

| 軸 | 層別キー | 記録の難易度 |
|---|---|---|
| Man | 作業者、班、シフト | 低 |
| Machine | 設備号機、金型、治具、ライン | 低 |
| Material | ロット番号、仕入先、材料グレード | 中（トレーサビリティ次第） |
| Method | 加工条件、手順バージョン、機種 | 中 |
| 時間 | 日付、曜日、時間帯 | 低 |

### 選び方

1. 4Mの各軸から「差が出そうな条件」を挙げる
2. 記録の負担が小さいものを優先する
3. **迷ったら入れる。** 記録しなかったキーは永久に分析できない
4. ただし項目が多すぎると記録が続かない。5〜7項目を上限の目安とする

### 層の水準数

各キーの水準（種類）が多すぎると、1水準あたりの件数が不足する。

- 目安：1水準あたり最低10件、望ましくは30件
- 例：作業者20人 × 各10件 = 200件が必要

**水準数 × 必要件数で総件数を見積もり、期間が現実的か確認する。**

## 4. チェックシート設計

### 2種類

| 種類 | 目的 | 形式 |
|---|---|---|
| 記録用 | データを取る | 分類項目 × 発生を記入する表 |
| 点検用 | 抜け漏れを防ぐ | 確認項目にチェックを入れるリスト |

### 記録用の設計要点

- **その場で書けること。** 後でまとめて書く形式は、記憶に頼るため精度が落ちる
- 記入は「正」の字やチェックなど、最小の手数で済むようにする
- 層別キーは選択式にする（自由記述にすると表記ゆれで集計できない）
- 記入例を1行入れておく
- 記入者・記入日を必ず入れる

### 点検用の設計要点

- 判断の余地がない表現にする（「適切に」「十分に」を使わない）
- 判定基準を数値で書く（「温度 60〜65℃」）
- 異常時の連絡先・処置を同じ紙に書く

### テンプレート
`assets/check-sheet.xlsx` を使う。

## 5. 必要な件数の目安

| 用途 | 最低件数 | 望ましい件数 |
|---|---|---|
| パレート図 | 50 | 100以上 |
| ヒストグラム | 30 | 100以上 |
| 管理図 | 20〜25群 | 25群以上 |
| 散布図 | 30組 | 50組以上 |
| 層別（1水準あたり） | 10 | 30以上 |

### 期間の見積もり

```
必要件数 ÷ 1日あたりの発生数 = 必要日数
```

**必要日数が現実的でない場合**は、以下を検討する。

- 層別キーを減らす（水準数を減らす）
- 対象範囲を広げる（他ラインも含める）
- 既存の記録から遡れないか確認する
- 定量分析をあきらめ、言語データの道具（`40_n7.md`）で進める

## 6. 既存データを使う場合の確認

「データはあります」と言われたら、以下を確認してから道具を決める。

| 確認項目 | 見るところ | 問題があった場合 |
|---|---|---|
| 件数 | 行数 | 不足なら追加取得を計画 |
| 期間 | 日付列の範囲 | 偏りがあれば注意して扱う |
| 層別キー | 列構成 | なければ追加取得を計画 |
| 欠損 | 空欄の割合 | 多ければ理由を確認する |
| 表記ゆれ | カテゴリ列の値の種類 | 名寄せしてから集計する |
| 単位 | 数値列の桁 | 混在していれば統一する |
| 異常値 | 最大・最小 | 入力ミスか実際の異常かを確認する |

**表記ゆれは実務で最も多い問題。** 「Aライン」「A line」「ライン A」が別カテゴリとして集計されると、パレート図が壊れる。

## 7. よくある失敗

| 失敗 | 結果 | 対処 |
|---|---|---|
| 層別キーを取らなかった | 差の有無が永久に分からない | 設計段階で迷ったら入れる |
| 合否だけ記録した | ばらつきが見えない | 可能な限り数値を記録する |
| 記録項目が多すぎた | 記録が続かない、精度が落ちる | 5〜7項目に絞る |
| 後でまとめて記入する運用 | 記憶に頼り精度が落ちる | その場で書ける形式にする |
| 自由記述にした | 表記ゆれで集計できない | 選択式にする |
| 件数を確認せず作図した | 誤った結論を出す | 作図前に必ず件数を確認する |
