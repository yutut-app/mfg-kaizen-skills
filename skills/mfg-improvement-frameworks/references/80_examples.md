# ケース1：寸法がばらつく

> A工程の外径がばらつく。規格 φ10.00 ±0.05。3ヶ月分420件のデータあり。

## 流れ

```
[現状] A工程 外径ばらつき  φ10.00±0.05  420件
   │
   ├─ データあり・層別キーあり → 要因解析は飛ばす（層別で事実を先に見る）
   ▼
[2 現状把握]
   │  ヒストグラム → 二山
   │  層別（号機・作業者・ロット）→ 号機で差
   ▼
[5 要因解析]
   │  散布図（切込み量 × 外径）→ 設定値の差で説明できる
   │  管理図 → 両号機とも安定
   │  結論：ばらつき拡大ではなく「2台の中心ずれ」
   ▼
[6 対策立案]
   │  5E → Engineering（設定統一・定期校正）
   ▼
[8 歯止め]
      QC工程表に号機別設定値を追加
      管理図で維持を監視
```

## 2 現状把握：ヒストグラム

```
   度数
    │           ┌─┐              ┌─┐
    │        ┌─┐│ │           ┌─┐│ │
    │     ┌─┐│ ││ │        ┌─┐│ ││ │
    │  ┌─┐│ ││ ││ │     ┌─┐│ ││ ││ │┌─┐
    └──┴─┴┴─┴┴─┴┴─┴─────┴─┴┴─┴┴─┴┴─┴┴─┴──
      9.96          9.99  10.01          10.04
             規格下限 9.95 │ 上限 10.05
```

| 見えた形 | 判断 |
|---|---|
| 山が2つ | 条件が混在している。**層別へ進む** |
| 規格内に収まっている | 現時点で不良は出ていないが、条件が違う以上いずれ外れる |
| 各山のばらつきは同程度 | ばらつき拡大ではない。**中心ずれ** |

中心ずれとばらつき拡大は**対策が真逆**。中心ずれは設定変更で直る。

## 2 現状把握：層別の結果表

**差が出なかったキーも必ず載せる。** 次に同じ調査を繰り返さずに済む。

| 層別キー | 水準 | 件数 | 平均 | ばらつき | 差 |
|---|---|---|---|---|---|
| 号機 | 1号機 | 210 | φ10.021 | 0.018 | **あり** |
| | 2号機 | 210 | φ9.979 | 0.019 | |
| 作業者 | 佐藤 | 145 | φ10.001 | 0.031 | なし |
| | 田中 | 138 | φ9.998 | 0.030 | |
| | 鈴木 | 137 | φ10.002 | 0.032 | |
| 材料ロット | L-2605〜2608 | 420 | — | — | なし |
| 時間帯 | 午前／午後 | 420 | — | — | 未確認 |

号機間で中心が0.042ずれている。**「ばらつきが大きい」のではなく「2台の設定が違う」。**

## 5 要因解析：散布図

層別で「号機が違う」までは分かった。**次は「号機の何が違うのか」を確かめる。**
切込み量の設定値と外径の関係を見る。

```
  外径
 10.05 ┤                              規格上限
 10.03 ┤          ●● ●
 10.01 ┤        ●●●●●●             ← 1号機（切込み 0.35）
  9.99 ┤   ○○○○○○
  9.97 ┤  ○○○ ○                    ← 2号機（切込み 0.32）
  9.95 ┼──────────────────────────  規格下限
       0.30   0.32   0.34   0.36
                切込み量 (mm)
```

- **層別して色分けする**（●1号機／○2号機）。全体で見ると関係が見えにくい
- 切込み量が大きいほど外径が大きい。**設定値の差が外径の差を説明できている**
- これで「号機が違う」から「設定値が違う」まで踏み込めた

相関があっても因果とは限らないが、この場合は加工原理から説明がつく。

## 8 歯止め：管理図

対策後、**維持できているかを監視する。** ここまでやって歯止め（標準化）が完結する。

```
  X̄ (mm)
 10.03 ┤- - - - - - - - - - - - - - - - - -  UCL 10.028
 10.01 ┤        ●   ●     ●   ●   ●
 10.00 ┤──●───●───●───●───●───●───●────  CL 10.000
  9.99 ┤  ●               ●
  9.97 ┤- - - - - - - - - - - - - - - - - -  LCL 9.972
       └────────────────────────────────
        7/1  7/8  7/15 7/22 7/29 8/5  8/12
              ↑ 設定統一（7/10）
```

| 判定項目 | 結果 |
|---|---|
| 管理限界の外れ | なし |
| 片側への連続 | なし |
| 上昇・下降の連続 | なし |
| 周期性 | なし |

**管理限界線と規格線は別物。** 管理限界は工程のばらつきから計算した値。
「規格内だから問題ない」と管理限界の外れを見逃さない。

## 8 歯止め：QC工程表への反映

| No. | 工程名 | 管理項目 | 規格・基準値 | 測定方法 | 頻度 | 責任者 | 異常時の処置 |
|---|---|---|---|---|---|---|---|
| 3 | 外径旋削 | **切込み量（1号機）** | 0.35mm | 設定値目視 | 段取り毎 | 1班 佐藤 | 停止し班長へ連絡 |
| 3 | 外径旋削 | **切込み量（2号機）** | 0.32mm | 設定値目視 | 段取り毎 | 1班 佐藤 | 同上 |
| 4 | 外径検査 | 外径 | φ10.00±0.05 | ノギス n=5 | 1時間毎 | 検査 田中 | 該当ロット全数選別 |
| 4 | 外径検査 | **X̄-R管理図** | 管理限界内 | 上記データを転記 | 日次 | 検査 田中 | 要決定（限界外れ時の判断者） |

太字は今回追加した箇所。**変更点が分かるようにする。**

# ケース2：ヒヤリハットが集まったが打ち手が決まらない

> ヒヤリハット報告が今月40件。多いのは「不注意」「確認不足」。どこから手を付けるか。

## 流れ

```
[現状] ヒヤリハット 40件・数値データなし
   │
   ├─ 最初にパレート図 → 「不注意 48%」で使えないと判明
   ▼
[5 要因解析]
   │  親和図で分類し直す → 「不注意」というグループが消える
   ▼
[2 現状把握]
   │  再集計してパレート図
   │  マトリックス図（件数 × 対策の実現性）
   ▼
[5 要因解析]
   │  安全工学の4Mで分解 → 足元グループは Media に集中
   ▼
[6 対策立案]
   │  5E → Environment / Engineering
   ▼
[8 歯止め]
      5S点検表に「床面の状態」を追加
```

## 1 テーマ選定：パレート図（失敗例 → 再分類後）

**最初に描いたものが使えなかった経緯ごと示す。**

最初の集計。

| 順位 | 分類 | 件数 | 構成比 |
|---|---|---|---|
| 1 | 不注意 | 19 | 48% |
| 2 | 確認不足 | 9 | 23% |
| 3 | 表示が見づらい | 3 | 8% |
| 4 | 床が滑る | 2 | 5% |
| 5 | その他 | 7 | 18% |

この図から出る結論は「注意喚起の徹底」。**毎年やって効果が出ていない対策。**
「不注意」は分類ではなく結論。「その他」が18%と大きいのも、分類が不適切な兆候。

## 1 テーマ選定：親和図

分類軸を先に決めず、報告の原文をカードにして集める。

```
┌─ 足元・通路に関するもの（7件）────────┐
│ 「A通路の床が濡れていて滑った」        │
│ 「台車のケーブルに足を引っかけた」      │
│ 「夜勤帯は搬入口が暗い」                │
└─────────────────────────────────────────┘

┌─ 表示・合図に関するもの（9件）────────┐
│ 「品番のラベルが似ていて取り違えかけた」│
│ 「クレーンの合図が聞こえなかった」      │
└─────────────────────────────────────────┘

┌─ 手順に関するもの（15件）──────────────┐
│ 「急いでいて確認を1つ飛ばした」          │
│ 「前工程と手順の解釈が違っていた」        │
└─────────────────────────────────────────┘

┌─ 体調・時間帯に関するもの（9件）───────┐
│ 「夜勤明けで判断が鈍っていた」          │
│ 「繁忙期で休憩が取れていなかった」      │
└─────────────────────────────────────────┘
```

**「不注意」というグループは消えた。** 原文に戻ると具体的な状況が書かれていたため。
見出しはカードの言葉から作る。結論を見出しにしない。

## 2 現状把握：再集計＋実現性

| 順位 | 分類 | 件数 | 構成比 | 対策の実現性 |
|---|---|---|---|---|
| 1 | 手順に関するもの | 15 | 38% | 中 |
| 2 | 表示・合図 | 9 | 23% | 高 |
| 3 | 体調・時間帯 | 9 | 23% | 低 |
| 4 | 足元・通路 | 7 | 18% | **高** |

件数だけなら手順が1位。しかし**足元は対策すれば確実に減る。**
件数の多寡と対策の効きやすさは別物なので、実現性の列を必ず添える。

## 6 対策立案：評価マトリックス

| 対策案 | 効果 | 実現性 | コスト | 副作用 | 判定 |
|---|---|---|---|---|---|
| A通路に防滑マットを敷く | ○ | ◎ | 小（3万円） | なし | **採用** |
| 搬入口の照明を増設 | ○ | ◎ | 小（8万円） | なし | **採用** |
| 品番ラベルの色分け | ◎ | ◎ | 小 | 前工程と調整要 | **採用** |
| 台車のケーブル配線を床下化 | ◎ | △ | 大（工事必要） | 停止1日 | 保留 |
| 夜勤体制の見直し | ◎ | × | 大 | 要員計画に影響 | 見送り |
| 注意喚起の朝礼追加 | △ | ◎ | なし | 形骸化しやすい | 見送り |

**見送った案とその理由も残す。** 後で「なぜやらなかったか」を必ず聞かれる。

# ケース3：客先クレームが再発する

> 同じ不良で客先から2回クレーム。1回目に対策したはずなのに。

## 流れ

```
[現状] 同一不良でクレーム2回目
   │
   ├─ 1回目の対策内容を確認 → 教育のみ・標準化なし
   │  → 要因解析はやり直さない
   ▼
[5 要因解析]
   │  なぜなぜ分析を2本立て（発生原因・流出原因）
   ▼
[2 現状把握]
   │  両系統とも「標準に書かれていない」で一致
   ▼
[5 要因解析]
   │  段取り替えの記録と不良発生日を突合せ
   ▼
[6 対策立案]
   │  ECRS → Simplify（チェックリスト集約）
   │  系統図で5E展開
   ▼
[8 歯止め]
      作業標準書・QC工程表・4M変更管理に反映
      効果確認を3ヶ月に延長
```

## 5 要因解析：なぜなぜ分析（2本立て）

**発生原因と流出原因を必ず分ける。** 片方だけでは客先に流れ続ける。

発生原因の系統

```
規格外の製品が作られた
 └ なぜ？ 段取り替え後の加工条件が標準から外れていた
    └ なぜ？ 段取り替え後に条件を確認していない
       └ なぜ？ 確認する手順が作業標準書にない  ← 真因
```

流出原因の系統

```
規格外品が客先へ流出した
 └ なぜ？ 抜取検査で当たらなかった
    └ なぜ？ 抜取は時間基準で、段取り替えとの関係を見ていない
       └ なぜ？ 段取り替え直後を重点検査する取り決めがない  ← 真因
```

1回目の対策（作業者への再教育）は**発生側にしか効いていない。**
流出側が手つかずだったため、2回目のクレームに至った。

「だから」で逆読みして繋がるか確認する。繋がらなければ論理が飛んでいる。

## 5 要因解析：突合せ

仮説をデータで確かめる。**表を2つ並べず、1つに突き合わせる。**

| 日付 | 段取り替え | 不良発生 | 一致 |
|---|---|---|---|
| 5/12 | あり（品番切替） | 3件 | ● |
| 5/13 | なし | 0件 | |
| 5/19 | あり（品番切替） | 2件 | ● |
| 5/20〜5/26 | なし | 0件 | |
| 6/2 | あり（金型交換） | 4件 | ● |

**不良は全て段取り替え当日に発生。** 仮説が裏付けられた。

## 6 対策立案：系統図

末端が「徹底する」「注意する」で終わっていたら展開不足。

```
段取り替えに起因する不良の流出をなくす
├─ ルールで守らせる（Enforcement）
│   ├─ 作業標準書に「段取り替え後の条件確認」を追加
│   │   ├─ 確認項目をチェックリスト1枚に集約  ← ECRS: Simplify
│   │   └─ 記録欄を設けて実施を残す
│   └─ QC工程表の管理項目に「段取り替え後の初品検査」を追加
├─ 技術で防ぐ（Engineering）
│   ├─ 加工条件を治具で物理的に固定する
│   └─ 条件が外れたら機械が起動しないようにする
└─ 仕組みに載せる（Management）
    └─ 段取り替えを4M変更管理の対象に登録
        └─ 次回の変更時に事前レビューを行う
```

1段目の展開に5Eを使う。**この案件では1回目が教育のみだったため、Education をあえて外している。**

## 8 歯止め：QC工程表への反映

| No. | 工程名 | 管理項目 | 規格・基準値 | 測定方法 | 頻度 | 責任者 | 異常時の処置 |
|---|---|---|---|---|---|---|---|
| 3 | 切削 | 加工条件（回転数） | 1,200rpm | 設定値目視 | **段取り毎** | 1班 佐藤 | 停止し班長へ連絡 |
| 3 | 切削 | 加工条件（送り） | 0.15mm/rev | 設定値目視 | **段取り毎** | 1班 佐藤 | 同上 |
| 4 | 検査 | 寸法 | φ20.00±0.03 | マイクロメータ | 1時間毎 | 検査 田中 | 該当ロット全数選別 |
| 4 | 検査 | **段取り替え後の初品** | 全項目 | 同上 | **段取り毎 n=3** | 検査 田中 | 要決定（NG時の遡り範囲） |

「要決定」を残すことで、次に何を決めればよいかが伝わる。

# ケース4：ラインを変えてから不具合が出る

> 先月レイアウトを変えた。それから組付け不良が増えた。原因は分かっているが戻せない。

## 流れ

```
[現状] レイアウト変更後に組付け不良が増加
   │
   ├─ 「原因は分かっている」の根拠を確認
   │   ・不良増加日 = 変更翌日
   │   ・他の3Mに変更なし
   │  → 施策実行型。要因解析を省略する
   ▼
[5 要因解析]
   │  4M × 3H で変化点を特定 → Method の変更1点
   │  変更内容をさらに展開
   ▼
[2 現状把握]
   │  マトリックス図で不良との関係を評価
   ▼
[5 要因解析]
   │  取り違えた部品の組み合わせを確認（簡易に済ませる）
   ▼
[6 対策立案]
   │  ECRS → Eliminate / Simplify
   ▼
[8 歯止め]
      レイアウト変更を4M変更管理の対象に登録
```

## 5 要因解析：4M × 3H 変化点表

空欄を残さず「該当なし」「未確認」と書く。

| 4M | 初めて | 変更 | 久しぶり |
|---|---|---|---|
| Man | 該当なし | 該当なし | 該当なし |
| Machine | 該当なし | 該当なし | 該当なし |
| Material | 該当なし | 該当なし | 該当なし |
| Method | 該当なし | **7/15 ラインレイアウト変更** | 該当なし |

**変更が1箇所に絞れている。** これが施策実行型を選ぶ根拠。

## 5 要因解析：変更内容の展開

「レイアウト変更」では粗すぎる。**何がどう変わったかまで割る。**

| 変わったこと | 不良との関係 | 確認方法 |
|---|---|---|
| 部品棚が作業者の背面になった | 取り違えの直接要因になりうる | 取り違えた部品の組み合わせを確認 |
| 作業動線が2m伸びた | 時間圧迫 → 確認省略の可能性 | 標準時間との差を測定 |
| 手元の照度が下がった | 目視確認の精度低下 | 照度測定（未実施） |

## 6 対策立案：ECRS

**排除から検討する。** 簡素化から入ると、不要な作業を効率化してしまう。

| 順 | 原則 | 検討 | 採否 |
|---|---|---|---|
| 1 | Eliminate | 部品棚まで移動する動作をなくせないか → 棚を正面に戻す | **採用** |
| 2 | Combine | 複数部品の取り出しをまとめられないか → キット化 | 保留（前工程と調整要） |
| 3 | Rearrange | 組付け順序を変えて取り違えを減らせないか | 効果小 |
| 4 | Simplify | 部品の色分け・形状違いで物理的に防ぐ | **採用** |

## 8 歯止め：4M変更管理への登録

| 変化点 | 区分 | 事前に行うこと | 事後に行うこと | 責任者 |
|---|---|---|---|---|
| レイアウト変更 | Method | 動線・照度・棚配置のレビュー | 変更後1週間の全数検査 | 製造課長 |
| 設備の移設 | Machine | 同上＋設備の据付精度確認 | 初品検査 | 保全課長 |
| 工程順序の変更 | Method | 前後工程への影響確認 | 要決定 | 要決定 |

**今回の再発防止だけでなく、次の変更にも効く仕組みにする。**

# ケース5：新しい工程を立ち上げる

> 来月から新機種の生産を開始。工程は新設。トラブルを事前に潰しておきたい。

## 流れ

```
[現状] 新工程・データなし
   │
   ├─ 定量の道具は全て使えないと確定
   ▼
[5 要因解析]
   │  4M × 3H（全マスが「初めて」）
   │  特性要因図（起きていない事象を想定）
   ▼
[2 現状把握]
   │  マトリックス図（発生可能性 × 影響 × 検出しやすさ）
   ▼
[5 要因解析]
   │  弱い。類似工程の実績と設備メーカー情報で補う
   │  確からしさが低いことを明記
   ▼
[6 対策立案]
   │  系統図で予防策
   │  PDPC で「それでも起きた場合」
   │  アローダイアグラムで立ち上げ日程
   ▼
[8 歯止め]
      QC工程表（仮）とチェックシートを事前に作成
```

## 5 要因解析：4M × 3H

| 4M | 初めて | 変更 | 久しぶり |
|---|---|---|---|
| Man | **全員が新機種を初経験** | 該当なし | 該当なし |
| Machine | **新設備2台を初稼働** | 該当なし | 該当なし |
| Material | **新規材料（供給元も新規）** | 該当なし | 該当なし |
| Method | **新工程・標準書は未作成** | 該当なし | 該当なし |

**全マスが「初めて」。これ自体が最も危険な状態であることを示している。**

## 3 目標設定：リスク評価マトリックス

未然防止では**「気づけるか」を必ず軸に入れる。** 発生頻度が低くても、
気づけない不具合は客先に流れる。

| 想定される不具合 | 発生可能性 | 影響 | 気づけるか | 優先度 |
|---|---|---|---|---|
| 新材料の硬度ばらつきで寸法不良 | 中 | 大 | ○（検査で分かる） | 2 |
| 新設備の熱変位で寸法が経時変化 | 中 | 大 | **×（初期は正常）** | **1** |
| 作業者の手順ミス | 高 | 中 | ○ | 3 |
| 供給元の納期遅延 | 低 | 大 | ○ | 4 |

**優先度1は発生可能性が最高ではない。** 気づけないことが決め手。

## 6 対策立案：PDPC

「うまくいく前提」の計画では意味がない。**失敗パターンを具体的に挙げることが本体。**

```
[出発] 新機種の量産開始

  ①初品検査を実施
      │
      ├─ 合格 ──────────────────────▶ ②へ
      └─ 不合格
           ├─ 寸法のみNG ──▶ 条件再調整 → 再度①
           └─ 複数項目NG ──▶ 設備メーカー立会 → 条件見直し → 再度①
                                （3日以内に解決しない場合は量産延期を判断）
                                 判断者：製造部長

  ②立ち上げ1週間 全数検査
      │
      ├─ 不良率 1%未満 ──────────────▶ ③へ
      └─ 1%以上
           ├─ 特定項目に集中 ──▶ 該当条件を層別で特定 → 対策
           └─ 分散している ────▶ 全数検査を継続しつつ工程能力を再評価

  ③抜取検査へ移行
      │
      └─ 移行後に不良発生 ──▶ 全数検査に戻す（判断者：品証課長）
                                 → 原因究明後に再移行

[目標] 安定生産・抜取検査での運用
```

各分岐に**判断者と期限**を入れる。入れないと、迷ったときに誰も決められない。

## 4 活動計画：アローダイアグラム

立ち上げ日程を組む。**クリティカルパスに資源を優先配分する。**

```
                    ┌─ 治具製作(10日) ─┐
                    │                    │
 設備据付 ─▶ 試運転 ─┤                    ├─▶ 初品検査 ─▶ 量産
  (5日)      (3日)  │                    │      (2日)
                    ├─ 標準書作成(7日) ─┤
                    │                    │
                    └─ 作業者教育(5日) ─┘
                       ※標準書完成後に開始
```

| 経路 | 所要 |
|---|---|
| 据付 → 試運転 → 治具製作 → 初品 | 5+3+10+2 = **20日** ← クリティカルパス |
| 据付 → 試運転 → 標準書 → 教育 → 初品 | 5+3+7+5+2 = 22日 ← **こちらが最長** |

**再計算すると教育経路が22日で最長。** 標準書作成の着手を前倒しできないかを検討する。
最長経路を見誤ると、日程が読めない。

# 付録：要因解析から対策立案への受け渡し

どのケースにも属さない。**道具の描き分けと、道具から道具への受け渡しを示すための設定。**

問題：「塗装のムラが減らない」

この付録で示すもの：

1. 特性要因図（中骨・小骨まで枝分かれさせた形）
2. 絞り込みの記録（残した要因・落とした要因とその根拠）
3. 目標設定の検算（部分と全体をつなぐ）
4. 系統図（特性要因図からの受け渡し）
5. 連関図との描き分け

変換規則の全体は `90_handoff.md`。

## 特性要因図（要因が階層で整理できる場合）

**中骨・小骨まで線で枝分かれさせる。** 大骨だけ線で描き、その先を箇条書きにしない。

```
          Man                                    Machine
           │                                        │
  教示が口伝 ─┐                           摩耗が進む ─┐
              ├─ スプレー距離のばらつき                 ├─ ノズルの状態不良
  距離ゲージなし ┘                         清掃頻度が低い ┘
           │                                        │
  標準速度が未定義 ─ 塗装速度の個人差        他設備と共用 ─ エア圧の変動
            ↘                                      ↘
─────────────────────────────────────────────────────────────────▶ 塗装ムラ
            ↗                                      ↗
  粘度の測定なし ─ 塗料の粘度差            乾燥時間が未規定 ─ 乾燥条件のばらつき
           │                                        │
  計量器がない ─┐                         回数の指示なし ─┐
                ├─ シンナー配合比のばらつき                ├─ 重ね塗り回数のばらつき
  配合が目分量 ─┘                         検査基準が曖昧 ─┘
           │                                        │
        Material                                 Method
```

| 階層 | この図での例 | 通称／JIS Q 9024 |
|---|---|---|
| 特性 | 塗装ムラ | 背骨／主軸 |
| 大骨 | Man / Machine / Material / Method | 大骨／大枝 |
| 中骨 | スプレー距離のばらつき | 中骨／小枝 |
| 小骨 | 教示が口伝、距離ゲージなし | 小骨／小枝 |

大骨に4M。要因が重複せず階層に収まっている。**この形で書けるなら特性要因図でよい。**

## 絞り込みの記録（ステップ5の出力）

**絞る単位は末端の要因（小骨）。** 大骨ごと残す／落とすをしない。
同じ大骨の中に残る要因と落ちる要因が混在するのが正常。

全体：塗装ムラ 45件 / 2500個 ＝ 1.8%（6月〜8月）。以下の層別はすべてこの45件・2500個を割ったもの。

| 大骨 | 末端の要因 | 判定 | 根拠（件数／母数） |
|---|---|---|---|
| Machine | 清掃頻度が低い | 残す | 号機別。清掃間隔の長い2号機 37件/1250個（3.0%）、1号機 8件/1250個（0.6%）。計 45件/2500個 |
| Machine | 他設備と共用 | 落とす | エア圧の実測値と不良に相関なし（散布図 n=52） |
| Man | 距離ゲージなし | 残す | 作業者別。目測している3名 33件/900個（3.7%）、他5名 12件/1600個（0.8%）。計 45件/2500個 |
| Man | 教示が口伝 | 落とす | 経験年数別で差なし（3年未満 20件/1100個＝1.8%、3年以上 25件/1400個＝1.8%）。層別で見えた条件差を説明できない |

**どの層別キーで割っても、件数の合計45件・母数の合計2500個が一致している。**
一致しない表は分類漏れか重複がある。

## 3 目標設定：部分と全体をつなぐ検算

```
現状        45件 ÷ 2500個 = 1.8%
削減見込み  30件（残した2要因に帰属する不良）
目標        (45 − 30) ÷ 2500 = 15件 ÷ 2500個 = 0.6%
到達下限    対象2要因の不良を全て0にしても残る 15件 ÷ 2500個 = 0.6%
```

**ゼロは目標にならない。** 対象要因を全部つぶしても 0.6% が残る。
残る15件（他の要因によるもの）は今回は触らない、と明記する。

## 6 対策立案：系統図（上の記録からの受け渡し）

**目的はステップ3の目標。1次手段は残った末端の要因を裏返して動詞化したもの。**
大骨（4M）は持ち込まない。落とした要因には展開しない。

```
目的                    1次手段              2次手段（実行可能な案）

塗装ムラを       ┌─ 清掃頻度を       ┌─ 清掃を段取り表の作業項目に組み込む
1.8%→0.6%に ────┤   下げない ───────┤
（9月末まで）    │                   └─ ノズル清掃済みを設備に表示する
                 │
                 └─ 距離を           ┌─ 距離ゲージを治具に固定する
                     目測させない ────┤
                                     └─ 距離が出ていないと噴射しない機構にする
```

| 末端の要因（名詞・状態） | 1次手段（動詞・行動） | 元の語 |
|---|---|---|
| 清掃頻度が低い | 清掃頻度を下げない | 清掃頻度 |
| 距離ゲージなし（目測している） | 距離を目測させない | 距離 |

**元の語を残す。** 「保全体制を強化する」と書くと、どの要因への手段か追えなくなる。
1次手段が否定形で止まるのは正しい。具体的な打ち手は2次以降で出す。

系統図の末端4案は、**全件がマトリックス図の評価対象**になる（`90_handoff.md` 第5章）。

## 連関図（要因が相互に影響し合う場合）

同じ問題でも、要因が絡み合っているとこうなる。

```
    エア圧の変動
         │
         ▼
   塗料の粒径ばらつき ──────▶ 塗装ムラ ◀────── 乾燥時間の不足
         ▲                      ▲                    ▲
         │                      │                    │
    ノズルの摩耗           重ね塗りで補正        タクトタイム短縮
         ▲                      │                    ▲
         │                      └────────────────────┘
    清掃頻度の低下                    （ムラを補正するため
         ▲                              さらに時間が不足する）
         │
    タクトタイム短縮
```

**「タクトタイム短縮」から矢印が2方向に出ており、循環が生じている。**
ムラを重ね塗りで補正すると、さらに時間が足りなくなって乾燥不足を招く。
この循環は特性要因図では表現できない。

## 判断の目安

| 状態 | 使う道具 |
|---|---|
| 要因が重複せず階層に収まる | 特性要因図 |
| 同じ要因が複数の大骨に出てくる | 連関図 |
| 要因同士が循環している | 連関図 |
| 迷っている | **まず特性要因図。** うまく分類できなければ切り替える |

# 使い方

1. 利用者の案件に最も近いケースを選ぶ
2. **流れの図を先に示す。** どのステップで何を作るかを共有してから個別の作業に入る
3. 各ステップの見本のレイアウトを借り、中身は利用者の工程名・数値・言葉で書く
4. 埋まらない欄は「未確認」「要決定」と書く。空欄にしない
5. **事例として見せるときは8ステップ全部を通す。** 一部だけだと、飛ばしたステップが
   「なぜ足りないのか」という指摘になる。使わないステップは飛ばした理由を1行で書く
6. **各ステップの末尾に「この道具で得たもの」「次にやること」を書く**（`90_handoff.md` 第1章）
7. **出した数値は全て検算する。** 表の縦計、率と件数（母数を併記）、
   層別の合計が元の値と一致するか、前後比較の条件が揃っているか
8. 見本の案件をそのまま出力しない
