## 1. 選び方

| 知りたいこと | 道具 | 最低限必要なデータ |
|---|---|---|
| どこに集中しているか | パレート図 | 項目別の件数・金額 |
| ばらつきの形 | ヒストグラム | 測定値 30件以上 |
| 時間的な安定性 | 管理図 | 時系列の測定値 20〜25群以上 |
| 2つの量の関係 | 散布図 | 対になった数値 30組以上 |
| 条件による差 | 層別 | 層別キーを持つデータ |
| 記録の仕組み | チェックシート | 不要（これから取る） |
| 要因の洗い出し | 特性要因図 | 不要（言語データ） |
| 大小・推移・割合 | グラフ | 用途による |

**件数の確認を先に行う。** 30件未満でヒストグラムを描いても形が読めない。

## 2. パレート図

項目別の件数を降順に並べ、累積比率を折れ線で重ねる。

### 使う場面
- テーマ選定：どこから手を付けるか
- 効果確認：対策前後の比較

### 手順
1. 分類項目を決める（不良の種類、工程、原因など）
2. 件数または金額を集計し、降順に並べる
3. 棒グラフ＋累積比率の折れ線を描く
4. 累積70〜80%までの項目を重点対象とする

### 読み方の注意
- **件数ではなく金額で描くと結論が変わることがある。** 損失額が問題なら金額で描く
- 「その他」が最大になったら分類が不適切。分類をやり直す
- 効果確認では**対策前と同じ分類・同じ期間長**で描く。条件を変えると比較にならない

## 3. ヒストグラム

測定値を区間ごとの度数で表す。分布の形を見る。

### 使う場面
- 現状把握：ばらつきの大きさと形
- 規格との関係を見る

### 手順
1. データを集める（30件以上、望ましくは100件以上）
2. 区間数を決める（データ数の平方根が目安）
3. 度数を数えて柱状に描く
4. 規格上限・下限がある場合は線を引く

### 形からの判断

| 形 | 疑うこと |
|---|---|
| 左右対称の山が1つ | 正常。安定している |
| 山が2つ（ふた山） | **異なる条件が混ざっている。層別する** |
| 片side に偏る | 選別・除去が行われている、または下限がある |
| 離れ小島 | 異常値・別ロットの混入 |
| 規格をはみ出す | 工程能力不足 |

**ふた山を見たら必ず層別する。** 設備別・作業者別・ロット別で分けると原因が見えることが多い。

## 4. 管理図

時系列で工程が安定しているかを見る。中心線と管理限界線を引く。

### 使う場面
- 現状把握：工程が安定しているか
- 効果確認：対策後に安定したか
- 日常管理：異常の早期検知

### 種類の選び方

| データの種類 | 使う管理図 |
|---|---|
| 測定値（長さ、重さなど）で群がある | X̄-R 管理図 |
| 測定値で1点ずつしか取れない | X-Rs 管理図 |
| 不良個数（サンプル数が一定） | np 管理図 |
| 不良率（サンプル数が変動） | p 管理図 |
| 欠点数（サンプル数が一定） | c 管理図 |
| 単位あたり欠点数 | u 管理図 |

### 異常の判定
- 管理限界線を外れる点がある
- 連続する点が中心線の片側に偏る
- 上昇または下降が続く
- 周期的な動きがある

**管理限界線と規格線は別物。** 管理限界は工程のばらつきから計算される値で、規格は要求値。混同しない。

---

## 5. 散布図

2つの量の関係を点でプロットする。

### 使う場面
- 原因追究：疑わしい要因と結果に関係があるか検証する

### 手順
1. 対になったデータを30組以上集める
2. 横軸に原因系、縦軸に結果系を取る
3. 点を打ち、傾向を見る
4. 必要なら層別して色分けする

### 読み方の注意
- **相関があっても因果とは限らない。** 第三の要因が両方に影響していることがある
- 全体では相関がなくても、層別すると相関が見えることがある（逆もある）
- 範囲が狭いと相関が見えにくい。条件を広げたデータが必要な場合がある

## 6. チェックシート

データを記録・集計するための帳票。**7つ道具で唯一、データを作る側の道具。**

### 2種類

| 種類 | 目的 |
|---|---|
| 記録用 | 現状把握のためにデータを取る |
| 点検用 | 抜け漏れを防ぐ（確認項目のチェック） |

設計の詳細は `60_data-design.md` を参照。

## 7. 層別

データを条件で分けて見る。**道具というより、他の道具に掛ける操作。**

### 層別キーの候補（4Mから選ぶ）

| 軸 | 層別キー |
|---|---|
| Man | 作業者、班、シフト、経験年数 |
| Machine | 設備号機、金型、治具、ライン |
| Material | ロット、仕入先、材料グレード |
| Method | 加工条件、手順バージョン、機種 |
| 時間 | 日付、曜日、時間帯、月 |

### 使い方
1. パレート図・ヒストグラム・管理図・散布図に対して層別を適用する
2. 層で差が出れば、そのキーが原因の手がかりになる
3. 差が出なければ、そのキーは原因ではない可能性が高い

**層別は原因追究の最短経路。** 特性要因図で要因を挙げる前に、まず層別で差が出るかを見た方が早いことが多い。

**層別できるかどうかは記録の設計で決まる。** 記録時にキーを取っていなければ後から層別できない。

---

## 8. 特性要因図

魚の骨の形で、結果（特性）に対する要因を階層的に整理する。

### 手順
1. 右端に解決すべき特性を置く（背骨）
2. **大骨に4Mを置く**（Man / Machine / Material / Method）
3. 各大骨から中骨・小骨へ「なぜそうなるか」を掘り下げる
4. 挙がった要因のうち、疑わしいものに印を付ける
5. **データで検証する**（層別、散布図）

### 注意
- **挙げただけでは仮説。** 必ずデータで確かめる
- 安全・ヒューマンエラーが対象なら大骨を安全工学の4Mにする
- 環境要因が絡むなら5M＋1E にする
- 要因が階層でなく相互に絡み合うなら、連関図（`40_n7.md`）に切り替える

大骨の選び方は `20_factor-axes.md` を参照。

## 9. グラフ

| 種類 | 用途 |
|---|---|
| 棒グラフ | 大小の比較 |
| 折れ線グラフ | 時間的な推移 |
| 円グラフ・帯グラフ | 構成比 |
| レーダーチャート | 複数項目のバランス |

**目的に対して形式が合っているかを確認する。** 推移を円グラフで描くなど、形式の誤用が多い。

## 10. 作図の実装方針

| 道具 | 実装 |
|---|---|
| パレート図、ヒストグラム、管理図、散布図、グラフ | データを読み込んで作図する |
| 特性要因図 | 図として描く（データ不要） |
| チェックシート | 表形式のテンプレートとして出力する |

### 作図前に必ず確認する
- 件数（本文冒頭の表の最低件数を満たすか）
- 層別キーの有無（列に何があるか）
- 欠損・異常値の扱い

**件数が足りない場合は作図せず、その旨を伝えて取得設計に切り替える。**
不足を隠して描いたグラフは誤った判断を招く。
