# 40_n7 — 新QC7つ道具（言語データ）

言葉・意見・アイデアなど**数値でないデータ**を整理する道具。データがなくても使える。
N7（New QC 7 Tools）とも呼ばれる。

## 1. 選び方

| 状況 | 道具 |
|---|---|
| 意見がバラバラで論点が見えない | 親和図法 |
| 原因が相互に絡み合っている | 連関図法 |
| 目的から手段へ展開したい | 系統図法 |
| 複数の案を評価軸で比べたい | マトリックス図法 |
| 日程・順序を組みたい | アローダイアグラム法 |
| 障害が予想され、迂回路が要る | PDPC法 |
| 数値化された多変量を整理したい | マトリックスデータ解析法 |

### QC7つ道具との使い分け

| | QC7 | 新QC7 |
|---|---|---|
| 扱うデータ | 数値 | 言語 |
| 主な場面 | 現状把握、効果確認 | テーマ選定、原因整理、対策立案、計画 |
| データがないとき | 使えない | **使える** |

**データがない案件では新QC7が主役になる。** 製造業以外にも広く使われる理由。

## 2. 親和図法

バラバラの言語データを、似たもの同士でグループ化して構造を見つける。KJ法に由来する。

### 使う場面
- テーマ選定：現場の声を整理して問題を特定する
- 課題達成型の攻め所の検討
- 何が問題かすら曖昧な段階

### 手順
1. 事実・意見を1枚1件でカードに書き出す
2. 似ていると感じるもの同士を集める（**分類基準を先に決めない**）
3. 集まったグループに見出しを付ける
4. グループ同士の関係を配置で表す

### 注意
**先に分類軸を決めてはいけない。** 決めた瞬間にただの仕分け作業になり、新しい構造が見えなくなる。
「なんとなく似ている」で集めてから、後で見出しを付けるのが要点。

## 3. 連関図法

要因同士が**原因と結果の関係で絡み合っている**場合に、矢印でつないで真因を探す。

### 使う場面
- 原因追究：特性要因図では整理しきれない複雑な問題
- 要因が相互に影響し合い、循環している場合

### 手順
1. 中央に問題を置く
2. 要因を書き出す（初期カードは4Mの各観点から出す）
3. 「AがBを引き起こす」関係を矢印でつなぐ
4. **矢印が多く出ている要因＝影響が大きい要因**
5. **矢印が多く入っている要因＝結果に近い要因**

### 特性要因図との使い分け

| | 特性要因図 | 連関図 |
|---|---|---|
| 構造 | 階層（木） | 網（相互関係） |
| 向く問題 | 要因が整理して分類できる | 要因が絡み合い循環する |
| 見つかるもの | 網羅的な要因リスト | 影響の大きい真因 |

**迷ったら特性要因図を先に描く。** 分類がうまくいかない、同じ要因が複数の大骨に出てくる、という状態になったら連関図に切り替える。

## 4. 系統図法

目的を達成するための手段を、階層的に枝分かれさせて展開する。

### 使う場面
- 対策立案：真因に対する打ち手を広く出す
- 課題達成型の方策立案

### 手順
1. 左端に目的（達成したいこと）を置く
2. 「そのためには何をするか」で1段展開する
3. 展開した各項目をさらに手段へ展開する（3〜4段）
4. 末端が実行可能なレベルになるまで続ける
5. 実行する案を選ぶ（選定はマトリックス図で行う）

### 注意
- **1段目の展開に5Eを使うと視野が広がる**（教育・技術・強化・模範・環境）
- 教育系の対策に偏りやすい。仕組みで防ぐ案（Engineering）を必ず含める
- 末端が「徹底する」「注意する」で終わっていたら展開不足

## 5. マトリックス図法

2つ以上の要素を行と列に配置し、交点で関係の有無や強さを見る。

### 使う場面
- 対策案の評価・選定
- 要因と結果の対応づけ
- 目標と手段の関連づけ

### 手順
1. 行と列に比較したい要素を置く
2. 交点に◎○△×などで関係の強さを記入する
3. 合計や重み付けで優先順位を出す

### 対策選定での評価軸

| 軸 | 見るもの |
|---|---|
| 効果 | どれだけ改善するか |
| 実現性 | 技術的・時間的にできるか |
| コスト | 費用・工数 |
| 副作用 | 他工程への影響 |

**QCD を評価軸に使うと、トレードオフが見える。** 効果だけで選ぶとコストや納期を圧迫する案を選びがち。

## 6. アローダイアグラム法

作業の順序と所要時間を矢印でつなぎ、全体日程とクリティカルパスを見る。PERT図とも呼ばれる。

### 使う場面
- 活動計画：改善活動のスケジュール
- 並行して進められる作業の把握

### 手順
1. 必要な作業を洗い出す
2. 前後関係（依存関係）を決める
3. 各作業の所要時間を見積もる
4. 矢印でつなぎ、最長経路（クリティカルパス）を求める

**クリティカルパス上の作業が遅れると全体が遅れる。** ここに資源を優先配分する。

単純な日程管理ならガントチャートで足りる。依存関係が複雑な場合にアローダイアグラムを使う。

## 7. PDPC法

Process Decision Program Chart。計画が思いどおりに進まない場合に備え、**分岐と迂回路をあらかじめ描く**。

### 使う場面
- 対策実施：失敗が予想される場面
- 課題達成型の成功シナリオ追究
- 未然防止型の対策立案

### 手順
1. 出発点と目標を置く
2. 想定される手順を並べる
3. 各段階で「うまくいかない場合」を想定する
4. その場合の代替ルートを描く
5. どのルートでも目標に到達できるか確認する

**「うまくいく前提」の計画しか描けていないなら、PDPCを使う意味がない。**
失敗パターンを具体的に挙げることが本体。

## 8. マトリックスデータ解析法

新QC7の中で唯一、**数値データを扱う**。多変量のデータを主成分分析などで少数の軸に要約する。

### 使う場面
- 多数の品質特性を持つデータの全体構造を見たい
- 官能評価の項目が多く、まとめたい

### 注意
統計解析の知識と専用の処理が必要。**他の6つに比べて実務での使用頻度は低い。**
利用者から明示的に求められた場合のみ扱い、それ以外は他の道具を提案する。

## 9. 作図の実装方針

| 道具 | 実装 |
|---|---|
| 親和図、連関図、系統図、アローダイアグラム、PDPC | 図として描く |
| マトリックス図 | 表として出力する |
| マトリックスデータ解析 | データ処理が必要 |

### 作図の前に
- **カード出しは利用者と一緒に行う。** Claudeが勝手に要因を想像して埋めると、現場の実態から離れる
- 材料が足りない状態で図だけ作らない。何を出せばよいかを問いかける
- 出た内容が現場の事実か、推測かを区別して扱う
