# 40_n7 — 新QC7つ道具（言語データ）

**言語データを整理して構造にするための道具。** 収束の側を担う。
QCストーリーの 1 テーマ選定 / 4 活動計画 / 5 要因解析（前半）/ 6 対策立案 で使う。

意見を出す発散（ブレーンストーミング）はこのスキルの対象外。
新QC7は**発散で出たものを受け取って構造化する**位置にある。

数値で絞り込み検証するのは `30_qc7.md`。**言葉で構造を作り、数値で確かめる**という
往復で使う（`00_mapping.md` 第2章）。

**データがない案件ではこちらが主役になる。**

全ての道具を同じ8項目で記述している。**比較して選ぶための構成。**

## 親和図法

**ひとことで**：バラバラの言語データを、似たもの同士でまとめて構造を見つける。KJ法に由来する。

**こう言われたら使う**
> 「意見がバラバラで論点が見えない」「報告が多すぎてどこから手を付ければいいか分からない」
> 「アンケートの自由記述をどうまとめればいいか」

**こういうときは使わない**
- 分類がすでに適切に付いている → パレート図で件数を見る方が速い
- カードが10枚未満 → グループ化する意味が薄い

**必要なもの**：言語データ（意見・報告・気づき）。1件1枚のカードにする。

**分かること**：自分たちが気づいていなかった論点の構造。

**手順**
1. 事実・意見を1枚1件でカードに書き出す
2. 似ていると感じるもの同士を集める
3. 集まったグループに見出しを付ける
4. グループ同士の関係を配置で表す

**実務での見極め**
- **分類軸を先に決めてはいけない。** 決めた瞬間にただの仕分けになり、新しい構造が見えない。「なんとなく似ている」で集めてから見出しを付ける
- **「不注意」「確認不足」のような結論めいた言葉が多数を占めていたら、この道具の出番**。もとの記述に戻ると、もっと具体的な状況が書かれている（`70_cases.md` ケース2）
- **件数の多寡で切り捨てない。** 少数意見に対策しやすい真因があることが多い

**よくある失敗**

| 症状 | 原因 | 対処 |
|---|---|---|
| 結局いつもの分類になった | 分類軸を先に決めた | カードから始め直す |
| グループの見出しが抽象的 | もとの記述に戻っていない | カードの言葉を使う |
| 1人でやって現場感がない | 文脈が抜けた | 報告した本人を入れる |

## 連関図法

**ひとことで**：要因を矢印でつなぎ、影響の大きいものを見つける。

**こう言われたら使う**
> 「原因が絡み合っていて整理できない」「対策してもまた別のところで問題が出る」
> 「特性要因図を描いたが、同じ要因が複数の大骨に出てくる」

**こういうときは使わない**
- 要因が階層で整理できる → 特性要因図の方が読みやすい
- 単一の変化点が起点になっている → 4M × 3H で足りる（`70_cases.md` ケース4）
- 要因が想定の域を出ない（未経験の工程）→ 精度が上がらない

**必要なもの**：言語データ。初期カードは4Mの各観点から出す。

**分かること**：影響の大きい要因（真因の候補）。

**手順**
1. 中央に問題を置く
2. 要因を書き出す
3. 「AがBを引き起こす」関係を矢印でつなぐ
4. 矢印の出入りを数える

**実務での見極め**
- **矢印が多く出ている要因＝影響が大きい**（対策の候補）
- **矢印が多く入っている要因＝結果に近い**（症状であって原因ではない）
- 特性要因図との使い分け：**階層なら特性要因図、循環なら連関図**。迷ったら特性要因図を先に描き、うまく分類できなければ切り替える

**よくある失敗**

| 症状 | 原因 | 対処 |
|---|---|---|
| 矢印だらけで読めない | 要因を絞っていない | 主要なものに限定する |
| 症状に対策してしまった | 矢印の向きを見ていない | 出ている矢印の多い方を選ぶ |

## 系統図法

**ひとことで**：目的を達成する手段を、階層的に枝分かれさせて展開する。**対策立案の中心。**

**こう言われたら使う**
> 「対策の案を出したい」「打ち手が思いつかない」「いつも同じ対策しか出てこない」

**こういうときは使わない**
- 対策が1つに決まっている → 展開する意味がない
- 目的が曖昧 → 先に現状把握へ戻る

**必要なもの**：達成したい目的（1つに絞られていること）。

**分かること**：実行可能なレベルまで具体化された対策案の一覧。

**手順**
1. 左端に目的を置く
2. 「そのためには何をするか」で1段展開する
3. 各項目をさらに手段へ展開する（3〜4段）
4. 末端が実行可能になるまで続ける
5. 実行する案を選ぶ（選定はマトリックス図で）

**実務での見極め**
- **1段目の展開に5Eを使うと視野が広がる**（教育・技術・強化・模範・環境）
- **教育に偏りやすい。** 「教育を徹底する」だけの対策は担当者が変われば消える。仕組みで防ぐ案（Engineering）を必ず含める
- 末端が「徹底する」「注意する」で終わっていたら展開不足

**よくある失敗**

| 症状 | 原因 | 対処 |
|---|---|---|
| 末端が精神論 | 展開が浅い | もう1〜2段掘る |
| 対策が全部教育 | 5Eを使っていない | 技術・環境の観点を足す |

## マトリックス図法

**ひとことで**：行と列に要素を置き、交点で関係の有無や強さを見る。

**こう言われたら使う**
> 「どの案を選べばいいか」「優先順位を付けたい」「要因と不良の対応を整理したい」

**こういうときは使わない**
- 選択肢が2つ以下 → 直接比較で足りる
- 評価軸が決まっていない → 先に軸を決める

**必要なもの**：比較したい要素と、評価軸。

**分かること**：優先順位。**評価軸の置き方で結論が変わる。**

**手順**
1. 行と列に要素を置く
2. 交点に◎○△×で関係の強さを記入する
3. 合計または重み付けで優先順位を出す

**実務での見極め**
- 対策選定の評価軸：効果／実現性／コスト／副作用
- **QCDを評価軸にするとトレードオフが見える。** 効果だけで選ぶとコストや納期を圧迫する案に偏る
- 未然防止では「**気づけるか**（検出しやすさ）」を軸に加える。発生頻度が低くても気づけない不具合は客先に流れる（`70_cases.md` ケース5）

**よくある失敗**

| 症状 | 原因 | 対処 |
|---|---|---|
| 全部◎になる | 軸が甘い | 相対評価にする |
| 選んだ案が実行されない | 実現性を見ていない | 軸に加える |

## アローダイアグラム法

**ひとことで**：作業の順序と所要時間を矢印でつなぎ、全体日程と最長経路を見る。

**こう言われたら使う**
> 「スケジュールを引きたい」「どこがボトルネックか知りたい」「並行して進められる作業は」

**こういうときは使わない**
- 依存関係が単純 → ガントチャートで足りる
- 作業が5つ以下 → 描く手間に見合わない

**必要なもの**：作業の一覧、前後関係、所要時間。

**分かること**：全体日程と、遅れが全体に響く経路（クリティカルパス）。

**手順**
1. 作業を洗い出す
2. 前後関係を決める
3. 所要時間を見積もる
4. 矢印でつなぎ、最長経路を求める

**実務での見極め**
- **クリティカルパス上の作業に資源を優先配分する。** ここが遅れると全体が遅れる
- クリティカルパス上にない作業は、多少遅れても影響がない

**よくある失敗**：所要時間の見積もりが楽観的すぎて、計画が最初から破綻する。

## PDPC法

**ひとことで**：計画が思いどおりに進まない場合に備え、分岐と迂回路をあらかじめ描く。

**こう言われたら使う**
> 「対策がうまくいかない場合に備えたい」「初めてやるので何が起きるか読めない」
> 「トラブルを事前に潰しておきたい」

**こういうときは使わない**
- 手順が確立していて失敗の余地がない → 不要
- 失敗パターンを具体的に挙げられない → 挙げられるまで情報を集める

**必要なもの**：出発点、目標、想定される手順。

**分かること**：どのルートを通っても目標に到達できるか。

**手順**
1. 出発点と目標を置く
2. 想定される手順を並べる
3. 各段階で「うまくいかない場合」を想定する
4. その場合の代替ルートを描く
5. 全ルートが目標に到達するか確認する

**実務での見極め**
- **「うまくいく前提」の計画しか描けていないなら、この道具を使う意味がない。** 失敗パターンを具体的に挙げることが本体
- 未然防止型では本領を発揮する。想定外は必ず起きるため（`70_cases.md` ケース5）

**よくある失敗**：分岐が「失敗したらやり直す」だけになる。具体的な代替手段を書く。

## マトリックスデータ解析法

**ひとことで**：多変量の数値データを、主成分分析などで少数の軸に要約する。
**新QC7で唯一、数値を扱う。**

**こう言われたら使う**
> 「品質特性が多すぎて全体像が見えない」「官能評価の項目が多くてまとめられない」

**こういうときは使わない**
- 項目が少ない → 散布図やマトリックス図で足りる
- **統計処理の環境や知識がない** → 他の道具を提案する

**必要なもの**：多変量の数値データ。

**分かること**：データ全体の構造、項目間の関係。

**手順**：専用の統計処理が必要。

**実務での見極め**：**他の6つに比べて実務での使用頻度は低い。**
利用者から明示的に求められた場合のみ扱い、それ以外は他の道具を提案する。

**よくある失敗**：結果の解釈が難しく、現場に説明できない。説明できない分析は使われない。
