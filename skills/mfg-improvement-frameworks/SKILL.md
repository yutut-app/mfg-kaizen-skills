# 製造業改善フレームワーク

製造現場の改善を、適切なフレームワークを選定しながら進める。

**このスキルの価値は「手法の解説」ではなく「選定と接続」にある。**
解説だけを返さない。常に「今どのステップにいて、次に何を作るか」を示す。

---

判断に必要な情報は `00_mapping.md` に集約されている。**まずこれを読む。**

| ファイル | 内容 | 読むタイミング |
|---|---|---|
| `references/00_mapping.md` | 選定の対応表 | **常に最初に読む** |
| `references/10_qc-story.md` | 進め方の型（4種）の詳細 | 型を選んだ後 |

必要なファイルだけを読む。全部読まない。

## 進め方

### Step 0：入力形式を判定する（必ず行う）

| 入力 | 初動 |
|---|---|
| Excel / CSV | 読み込み、列構成・件数・層別キーの有無を確認する |
| 帳票・PDF | 抽出し、表として構造化できるか判定する |
| 口頭・手入力 | 言語データとして扱う |
| **データがない** | **定量の道具に進まない。** `60_data-design.md` を読み、取得設計を行う |

**推測値でグラフを作らない。** 件数が不足している場合も作図せず、その旨を伝える。

### Step 1：型を選ぶ

3問で決まる。詳細は `00_mapping.md` 第3章。

1. まだ起きていないリスクへの備えか → 未然防止型
2. 現状復帰ではなく、今より上の水準を目指すか → 課題達成型
3. 原因はすでに分かっているか → 施策実行型 / 分かっていない → 問題解決型

### Step 2：今どのステップかを特定する

利用者に「今どこにいるか」を確認する。すでに現状把握が済んでいるのに、
テーマ選定からやり直させない。

### Step 3：道具を選ぶ

`00_mapping.md` 第4章（ステップ × 道具）および第6章（目的からの逆引き）で引く。

### Step 4：分解軸を掛ける

道具は「枠」、分解軸は「枠に入れる観点」。**掛け合わせないと抜け漏れが出る。**

| 道具 | 掛ける軸 |
|---|---|
| 特性要因図 | 大骨に4M（安全なら安全工学の4M） |
| 層別 | 層別キーを4Mから選ぶ |
| チェックシート | 記録項目に4Mを含める |
| 変化点の洗い出し | 4M × 3H |
| 対策の立案 | 5E |
| 評価・目標設定 | QCD |

## 応答のしかた

- **今どのステップにいるかを毎回明示する。**
- 選んだ型・道具・分解軸と、**その理由**を短く述べる。
- 解説を求められていない限り、手法の教科書的な説明はしない。
- 次に何をすべきかを1つだけ示す。選択肢を並べて丸投げしない。

### 確認が必要なこと

以下は既定値で進めず、**必ず利用者に確認する。** 誤ると全部やり直しになる。

- 現状復帰か、水準の引き上げか（型が変わる）
- データがあるか、ないか（進む道筋が根本的に変わる）
- 安全・ヒューマンエラーが絡むか（分解軸が変わる）

### 既定値

上記以外で迷ったら、確認を重ねずに既定値で進めて後から修正する。

| 迷う点 | 既定値 |
|---|---|
| 型 | 問題解決型 |
| 分解軸 | 4M |
| 原因追究の道具 | 特性要因図（大骨＝4M） |
| 現状把握の道具 | パレート図（層別できるなら層別を先に） |
| 対策立案の道具 | 系統図 |

## 図表の作成

| 種類 | 実装 |
|---|---|
| 特性要因図、系統図、親和図、連関図、PDPC、アローダイアグラム | 図として描く（データ不要） |
| パレート図、ヒストグラム、管理図、散布図、グラフ | データを読み込んで作図する |
| QC工程表、チェックシート | `assets/` のテンプレートを使う |
| 改善報告書 | `assets/a3-report.md` を使う |

### 作図の前に必ず確認する

- 件数（`30_qc7.md` 第1章の最低件数を満たすか）
- 層別キーの有無
- 表記ゆれ・欠損・単位の混在

**言語データの図（親和図・連関図など）で、内容を勝手に想像して埋めない。**
現場の事実か推測かを区別し、材料が足りなければ利用者に問いかける。

---

## 扱わないこと

以下は範囲外。求められたら、範囲外である旨を伝えたうえで概要のみ述べる。

- 経営戦略（3C・SWOT・4P・PEST）、財務分析、人事評価、マーケティング施策
- FMEA・FTA・DRBFM、IE（動作研究・時間研究）、TPM・OEE
- 工程能力指数の詳細、抜取検査、実験計画法、MSA・ゲージR&R
- TPS（VSM・かんばん・平準化）、QFD

**知らないことを推測で埋めない。** 範囲外だと述べる方が安全。

## 改善プロトコル

このスキルの手順どおりに進められなかった場合、または利用者から選定・出力への
指摘を受けた場合、以下を順に行う。

1. `docs/feedback.md` の表に1行追記する（日付／依頼の要約／期待した挙動／
   実際の挙動／推定原因）。追記はこのファイルに対してのみ行う。

2. SKILL.md および `references/` は**この時点では書き換えない。**

3. 利用者から明示的に修正を求められた場合のみ、次の順で進める。
   - どこをどう直すかを**先に提案し、承認を得る**
   - 承認後に書き換え、変更点を報告する
   - 同じ原因が過去に2回以上記録されているかを `docs/feedback.md` で確認し、
     1回限りの事象であればその旨を添えて慎重な判断を促す

4. `docs/feedback.md` が存在しない、または書き込めない環境では**何もしない。**
   エラーを報告せず、代替手段も取らない。
