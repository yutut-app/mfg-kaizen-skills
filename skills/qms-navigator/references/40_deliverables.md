# 帳票カード — 役割ごとに1枚

**照合状況：未照合（知識による）。** 条項番号は `00_iso9001-base.md` と業界の層の照合状況に従う。

帳票は会社・業界で名前が違う。ここでは**役割**で1枚ずつ持ち、呼び名は「別名」に並べる。
実物の名前がどのカードに当たるかは、別名で引く。当たるカードが無ければ「該当カードなし」と書き、近いカードで読んだことを明記する。

**このファイルは作り方を持たない。** 実物を読み、良し悪しを見分けるためのもの。

## 要求の流れ — 引継ぎの順

```
C1 要求仕様 ─→ C2 要求の追跡表 ─────────────────────────────→（全帳票の行き先を記録）
                 └→ C3 設計リスク分析 ─→ C4 特殊特性一覧
                        │                    ├→ C6 図面（記号）
                        └→ C5 設計検証計画     └→ C7 工程リスク分析 ─→ C8 工程管理計画 ─→ C9 作業標準
                           （C3 の検出管理が                                 ├→ C10 測定システム評価
                             試験項目になる）                                └→ C11 工程能力
                                                                  C3〜C11 一式 ─→ C12 製品承認 ─→ C13 量産開始
```

検査では、この流れに沿って**引継ぎ表**（SKILL.md 手順4）を埋める。

## C1 要求仕様

| 項目 | 内容 |
|---|---|
| 目的 | 顧客が何を求めているかを、製品・品質・納入・法規の面から定める |
| 受け取る → 渡す | 顧客 → C2 要求の追跡表、C3 設計リスク分析の機能の欄 |
| 紐づく条項 | ISO 8.2.2・8.2.3（要求の明確化とレビュー）、8.3.3（設計インプット）。自動車は 4.3.2（顧客固有要求）、8.2.3.1.3（番号未照合）（製造フィージビリティ） |
| 読み方 | 機能・性能・寿命・環境条件・法規・外観・梱包・顧客固有要求に分けて、それぞれ数値と試験方法まで書かれているか |
| 成熟度 | 受注前は「受けられるか」の判定材料。設計中に変更されたら版と変更点が追えること |
| よくある不備 | 数値の無い要求（「十分な強度」）。法規要求や顧客固有要求が別文書のまま本体から参照されていない。版管理が無く、どの版で設計したか分からない |
| 質問例 | 「この要求の判定基準と試験方法はどの文書に定められていますか」 |

## C2 要求の追跡表

| 項目 | 内容 |
|---|---|
| 目的 | 要求1件ごとに、どこで満たし、どこで確かめたかを追う。**要求が途中で落ちていないことの証拠** |
| 受け取る → 渡す | C1 → C3・C5・C6・C8 の該当箇所への参照 |
| 紐づく条項 | ISO 8.2.3、8.3.3、8.3.4。自動車は 8.2.3.1.3（番号未照合）（製造フィージビリティ）、8.3.3.1（番号未照合）（製品設計インプット） |
| 読み方 | 行＝要求。列＝対応する設計（図面・仕様の箇所）、検証（C5 の試験番号）、工程（C8 の管理項目）、判定。**空欄の列が無いか**を見る |
| 成熟度 | P1 は「対応方針と受けられるか」まで。P4 で検証の列、P6 で工程の列が埋まる |
| よくある不備 | 要求を写しただけで行き先の列が無い。「対応済」とだけ書き、どの文書のどこかが無い。顧客の仕様変更が追跡表に反映されていない |
| 質問例 | 「要求 No.◯ を確かめた試験は、設計検証計画のどの項目ですか」 |

## C3 設計リスク分析

| 項目 | 内容 |
|---|---|
| 目的 | 設計に起因する故障を先に洗い出し、重大なものから設計で手を打つ |
| 受け取る → 渡す | C1・C2 の機能 → C4（重大度の高い特性）、C5（検出管理＝確かめる試験）、C7（設計で残った工程側のリスク） |
| 紐づく条項 | ISO 6.1、8.3.3、8.3.5。自動車は 8.3.3.3（特殊特性）、10.2.3（不具合が出たら更新） |
| 読み方 | 自動車の FMEA の読み方は `sectors/automotive-iatf.md` の FMEA。要点：機能 → 故障モード → 影響（重大度）→ 原因 → 予防（設計上の手当て）→ 検出（**検証試験**）→ 処置 → 再評価 |
| 成熟度 | **初期版**：機能と故障の洗い出し、重大度、処置の計画。**最新版**：C5 の結果を反映して発生度・検出度を見直し、処置後の再評価が埋まり、未完了が無い |
| よくある不備 | 初期版のまま詳細設計のゲートを通る。設計の検出管理に「工程の検査」を書く（設計を確かめる手段ではない）。C5 の試験と対応していない。類似製品の不具合が入っていない |
| 質問例 | 「重大度が最も高い故障モードの検出管理は、設計検証計画のどの試験ですか」 |

## C4 特殊特性一覧

| 項目 | 内容 |
|---|---|
| 目的 | 安全・法規・機能に効く特性を特定し、図面から工程・作業まで特別な管理をかける |
| 受け取る → 渡す | 顧客指定＋C3 の重大度 → C6 の記号、C7・C8・C9 の記号と管理 |
| 紐づく条項 | 自動車は 8.3.3.3（特殊特性）。ISO では 8.5.1 の管理の重み付けに当たる |
| 読み方 | 特性ごとに：区分（安全・法規・機能など、顧客の記号）、規格値、根拠（顧客指定か C3 か）、**展開先（図面・C7・C8・C9）の有無** |
| 成熟度 | P3 で候補 → P5 終了までに全展開先へ記号が入る |
| よくある不備 | 一覧はあるが C8 や C9 に記号が無い。顧客の記号と社内の記号の対応表が無い。重大度が高いのに特殊特性にしなかった理由が書かれていない |
| 質問例 | 「特殊特性◯は、コントロールプランと作業標準のどこで管理されていますか」 |

## C5 設計検証計画と結果

| 項目 | 内容 |
|---|---|
| 目的 | 設計が要求を満たすことを、試験で確かめる計画と結果 |
| 受け取る → 渡す | C1・C2 の要求、C3 の検出管理 → 結果を C3 の再評価と C2 の検証列へ |
| 紐づく条項 | ISO 8.3.4（検証・妥当性確認）。自動車は 8.3.4.2（番号未照合）（設計・開発の妥当性確認）、8.3.4.3（番号未照合）（試作プログラム） |
| 読み方 | 試験ごとに：対応する要求、試験方法（規格番号）、合否基準、**サンプル数と、その根拠**、試作品の条件（どの工程で作ったか）、実施時期、結果、合否、責任者 |
| 成熟度 | 計画（P3）→ 結果（P4）。量産工程で作った品での確認（工程側の妥当性確認）は P6 で別に行うことが多い |
| よくある不備 | 要求に対応しない試験、試験の無い要求。合否基準が「異常なきこと」。サンプル数が 1〜3 で根拠が無い。不合格の扱い（再試験・設計変更）が書かれていない。試作品が量産と違う工法で、その差が評価されていない |
| 質問例 | 「試験◯のサンプル数の根拠と、試作品の製造条件をご提示ください」 |

## C6 図面

| 項目 | 内容 |
|---|---|
| 目的 | 製品の形・寸法・公差・材料・注記を定める、製造と検査の基準 |
| 受け取る → 渡す | C1・C3・C4 → C7（工程で作り込む特性）、C8（管理特性）、C12（寸法測定結果の元） |
| 紐づく条項 | ISO 8.3.5（設計アウトプット）、7.5（文書管理）。自動車は 8.3.5.1（番号未照合）（設計アウトプット） |
| 読み方 | 版と承認、材料指定、一般公差、幾何公差、注記（表面処理・熱処理・規格の参照）、**特殊特性の記号**、顧客図面との対応 |
| 成熟度 | P3 で正式版。以後は変更履歴と、変更の工程・承認への波及を追う |
| よくある不備 | 特殊特性の記号漏れ。注記で参照する規格の版が無い。現場の図面が旧版。測定できない公差（測定方法が決まっていない） |
| 質問例 | 「図面注記◯の要求は、どの工程でどう管理していますか」 |

## C7 工程リスク分析

自動車の PFMEA の読み方は `sectors/automotive-iatf.md` の FMEA を参照する。共通の要点だけここに置く。

| 項目 | 内容 |
|---|---|
| 受け取る → 渡す | 工程の流れ図、C4、C3 の工程側に残るリスク → C8（予防・検出の管理をそのまま写す） |
| 成熟度 | P5 で作成 → 量産試作で出た不具合を反映 → 量産後も不具合・変更のたびに更新 |
| 見る点 | **C4 の特殊特性がすべて載っているか**。工程の流れ図と工程番号が一致するか |

## C8 工程管理計画

自動車のコントロールプランの読み方は `sectors/automotive-iatf.md` を参照する。

| 項目 | 内容 |
|---|---|
| 受け取る → 渡す | C7 の予防・検出管理、C4 → C9（作業の中身）、C10（載っている測定器）、C11（管理する特性） |
| 別名の注意 | 日本の「QC工程表」はコントロールプランと役割が近いが、反応計画（異常時の処置）の欄が無い様式がある。**無ければ抜けとして扱う** |
| 成熟度 | 試作用 → 量産試作用 → 量産用。段階の区別が書かれているか |

## C9 作業標準

| 項目 | 内容 |
|---|---|
| 目的 | 作業者が、決めた方法で毎回同じに作業するための指示 |
| 受け取る → 渡す | C8 の管理項目、C4 → 現場 |
| 紐づく条項 | ISO 8.5.1（管理された条件）、7.5（文書管理）。自動車は 8.5.1.2（標準作業）、8.5.1.3（段取り替えの検証） |
| 読み方 | 作業手順、急所（品質を左右するポイント）、**C8 と同じ管理項目・頻度・判定基準**、特殊特性の記号、異常時の処置（止める・呼ぶ・待つ）、使う治具・測定器、版と承認 |
| 成熟度 | 量産試作で現場検証済みであること（書いた人ではなく作業者が使えるか） |
| よくある不備 | C8 と頻度・基準が違う。特殊特性の記号が無い。異常時の処置が無い。現場の掲示が旧版。作業者の言葉で書かれていない |
| 質問例 | 「コントロールプランの工程◯の管理項目は、作業標準のどの手順で実施していますか」 |

## C10 測定システム評価

読み方は `sectors/automotive-iatf.md` の MSA。共通の見る点：**C8 に載っている測定器・判定方法のすべてが評価済みか**（計数値の判定＝目視・ゲージの合否も含む）。

## C11 工程能力

読み方は `sectors/automotive-iatf.md` の SPC。共通の見る点：**C4 の特殊特性すべてに工程能力の結果があるか**、量産条件（設備・作業者・材料ロット・時間）で取ったデータか、安定を確かめてから能力を出したか。

## C12 製品承認

自動車の PPAP の読み方は `sectors/automotive-iatf.md` を参照する。共通の見る点：**C3〜C11 が同じ版・同じ工程番号でそろっているか**、顧客の承認記録（自社の判断ではなく）があるか。他業界の別名：航空宇宙の FAI（初回製品検査、AS9102）、医療の設計移管・プロセスバリデーションの記録。

## C13 量産開始・初期流動の判定

| 項目 | 内容 |
|---|---|
| 目的 | 量産を始めてよいかの判定と、立上げ直後を強化した管理（初期流動管理）で見守り、通常管理へ移す判定 |
| 受け取る → 渡す | C12 の承認、P6 の未完了事項 → 量産（通常の C8） |
| 紐づく条項 | ISO 8.1、8.6（リリース）。自動車は 8.3.4.4（製品承認）、顧客固有要求で初期流動管理（GP-12 などの名で）が定められることが多い |
| 読み方 | 判定基準（何を満たしたら開始・解除か）、未完了事項と期限、初期流動の強化内容（全数検査・頻度増し・監視指標）、**解除の条件と期間**、判定者 |
| 成熟度 | 開始判定（P7 の入口）→ 解除判定（P7 の出口） |
| よくある不備 | 「関係者合意」だけで基準が無い。未完了事項を持ち越すが期限と責任者が無い。初期流動の解除条件が無く、だらだら続くか、根拠なく解除される |
| 質問例 | 「初期流動管理の解除条件と、現在の達成状況をご提示ください」 |
