# 業界の層 — 自動車（IATF 16949:2016 とコアツール）

照合状況：**全行 未照合（知識による要約）**。IATF の条項番号は細かく、記憶違いが起きやすい。
判定の根拠に番号を使うときは「番号未照合」と添える。

## 規格の関係

- IATF 16949 は単独では使えない。**ISO 9001 の本文と合わせて読む**追加要求の集まり。条項番号は 9001 の番号に枝番を足した形（例：8.3.3.3）
- 要求の階層は3段：**ISO 9001 → IATF 16949 → 顧客固有要求（CSR）**。CSR が IATF より優先されることが多い
- コアツールは IATF の本文ではなく、AIAG（米）や VDA（独）の手引書。**どの手引書・どの版に拠るかは CSR で決まる**
- 認証は IATF が承認した認証機関のみ。解釈は IATF が公開する SI（公式解釈）と FAQ で補われる

## コアツール — 実物を読むために

**作り方は持たない。読んで良し悪しを見分けるための知識だけ。**
最初に必ず「どの手引書・どの版で作られた文書か」を確かめる。版で様式と評価方法が違う。

### ツールのつながり（ここが切れていたら最初に突く）

```
APQP（計画の枠組み）
 └ 図面・仕様の特殊特性
     ├ DFMEA（設計の故障）
     └ プロセスフロー図 → PFMEA（工程の故障）→ コントロールプラン → 作業指示
                                                    ├ MSA（測定は信用できるか）
                                                    └ SPC（工程は安定し、能力があるか）
 └ PPAP（上の一式を顧客に出して量産承認を得る）
```

**同じ工程番号・同じ特性名が、フロー図 → PFMEA → コントロールプラン → 作業指示まで一致していること。**
一致しない所は、管理の抜けが起きている所。

### APQP（先行製品品質計画）

| 項目 | 内容 |
|---|---|
| 何のためか | 新製品を量産まで持っていく段階計画。5段階（計画 → 製品設計 → 工程設計 → 製品・工程の妥当性確認 → 量産・改善）とゲート |
| 紐づく条項 | 8.1, 8.3, 8.3.2.1 |
| 読み方 | 段階ごとの出力物が揃っているか、ゲートで誰が判定したか、未完了項目と期限 |
| よくある不備 | 部門横断チームが名ばかり。未完了項目が「継続」のまま次段階へ進む |
| 先方への質問の例 | 「量産試作段階の未完了項目と、完了予定日をご提示ください」 |

### FMEA（故障モード影響解析）

| 項目 | 内容 |
|---|---|
| 何のためか | 起こりうる故障を先に洗い出し、重大なものから予防・検出の手を打つ。DFMEA（設計）と PFMEA（工程） |
| 紐づく条項 | 8.3.3.3, 8.5.1.1, 10.2.3（不具合が出たら更新） |
| 版の違い | **AIAG 第4版**：S（影響度）×O（発生度）×D（検出度）＝RPN で優先度。**AIAG-VDA 2019**：7ステップ、RPN を使わず AP（処置優先度 H/M/L）で判定。構造・機能・故障のつながりを書く |
| 読み方 | 工程（機能）→ 故障モード → 影響（S）→ 原因 → 予防管理（O）→ 検出管理（D）→ 優先度 → 処置 → **処置後の再評価** |
| よくある不備 | 処置後の再評価欄が空。**予防管理と検出管理の混同**（検査は予防ではない）。S が高いのに処置なし。原因が「作業ミス」だけ。**実際に出た不良・クレームが故障モードに入っていない**。特殊特性が載っていない。版が混在（AP の様式に RPN を書く） |
| 先方への質問の例 | 「S=9以上の項目について、処置後の評価結果をご提示ください」「昨年度のクレーム◯件は、PFMEA のどの行に反映されていますか」 |

### コントロールプラン（管理計画）

| 項目 | 内容 |
|---|---|
| 何のためか | 工程ごとに、何の特性を、何で、どれだけの頻度で測り、外れたら何をするか。PFMEA の結論を現場の管理に落としたもの |
| 紐づく条項 | 8.5.1.1, 8.3.3.3, 8.5.6.1.1 |
| 読み方 | 工程番号、特性（製品・工程）、特殊特性の記号、規格値、測定方法、サンプル数と頻度、管理方法、**異常時の処置（反応計画）** |
| よくある不備 | 反応計画が「上司に報告」だけ。PFMEA の検出管理と中身が違う。特殊特性の記号漏れ。MSA をしていない測定器が載っている。段階（試作・量産試作・量産）の区別が無い |
| 先方への質問の例 | 「工程◯の特殊特性△が規格外になった場合、製品の隔離範囲はどう決めますか」 |

### MSA（測定システム解析）

| 項目 | 内容 |
|---|---|
| 何のためか | 測った値が信用できるか。測定のばらつきが、製品のばらつきや公差に比べて小さいか |
| 紐づく条項 | 7.1.5.1.1 |
| 主な手法 | 計量値：**ゲージ R&R**（繰返し性・再現性）、偏り、直線性、安定性。計数値（合否判定）：一致率・カッパ係数などの計数値 MSA |
| 読み方（ゲージ R&R） | **%GRR**：10% 未満は良、10〜30% は用途次第で条件付き、30% 超は不可（AIAG の一般的な目安、CSR で上書きされうる）。**ndc**（区別できる区分数）5以上。**分母が「公差」か「工程変動」かを確かめる**（同じデータでも値が変わる） |
| よくある不備 | サンプルが工程のばらつきを代表していない（似た部品ばかり選ぶ）。10〜30% を無条件に合格。外観検査など計数値の判定で MSA をしていない。測定者1人で再現性を評価できていない |
| 先方への質問の例 | 「%GRR の分母は公差と工程変動のどちらですか」「評価に使った10個のサンプルは、どう選びましたか」 |

### SPC（統計的工程管理）

| 項目 | 内容 |
|---|---|
| 何のためか | 工程が安定しているか（管理図）、規格に対して能力が十分か（工程能力指数） |
| 紐づく条項 | 9.1.1.1, 8.5.1.1 |
| 読み方 | **安定が先、能力が後。** 管理図で異常（管理限界外、連、傾向）が無いことを確かめてから Cpk を読む。**Cpk は安定した工程でしか意味を持たない** |
| 目安（一般的、CSR で上書きされうる） | 量産で Cpk 1.33 以上、新工程の初期（Ppk）で 1.67 以上がよく使われる |
| よくある不備 | 管理限界に規格値を書いている。不安定な工程の Cpk を出している。データ数が少なすぎる。Cpk と Ppk の取り違え。異常点に処置の記録が無い |
| 先方への質問の例 | 「この Cpk は、管理図で安定を確認した期間のデータですか」 |

### PPAP（生産部品承認プロセス）

| 項目 | 内容 |
|---|---|
| 何のためか | 量産前に、顧客要求を満たす部品を安定して作れる証拠一式を出し、承認を得る |
| 紐づく条項 | 8.3.4.4, 8.5.6.1 |
| 構成 | 18要素（設計記録、技術変更文書、顧客の設計承認、DFMEA、プロセスフロー図、PFMEA、コントロールプラン、MSA、寸法測定結果、材料・性能試験結果、初期工程調査、試験所の資格、外観承認、サンプル製品、マスターサンプル、検査補助具、顧客固有要求への適合記録、**部品提出保証書（PSW）**）と、提出水準 レベル1〜5（標準はレベル3）。欧州系の顧客は VDA の PPA を使うことがある |
| 読み方 | 要求された提出水準の要素が揃っているか。**寸法測定結果が図面の全寸法を網羅しているか**。PSW の記載（理由、水準、重量、署名）。フロー図 → PFMEA → コントロールプランの一致 |
| よくある不備 | 寸法の抜け（特に注記寸法）。初期工程調査のデータが量産条件でない。材料証明が古い。変更時に再提出していない |
| 先方への質問の例 | 「図面注記◯の寸法の測定結果が見当たりません」「初期工程調査は、量産設備・量産作業者の条件で取ったものですか」 |

### 8D（問題解決の報告書式）

IATF の本文にある名前ではないが、10.2.3 の「決められた問題解決手法」として顧客がよく指定する。

| 項目 | 内容 |
|---|---|
| 構成 | D1 チーム → D2 問題の記述 → D3 暫定処置（封じ込め）→ D4 根本原因（**発生原因と流出原因の両方**）→ D5 恒久対策の選定 → D6 実施と効果確認 → D7 再発防止（水平展開、FMEA・コントロールプラン更新）→ D8 チームの承認 |
| よくある不備 | **流出原因（なぜ検査で止められなかったか）が無い**。根本原因が「作業者の不注意」「教育不足」。D6 の効果がデータで示されていない。D7 で FMEA 更新の証拠が無い。封じ込めの範囲（在庫・輸送中・顧客在庫）が曖昧 |
| 先方への質問の例 | 「流出原因と、その対策をご提示ください」「対策後の不良率の推移を、対策前と同じ単位でご提示ください」 |

原因分析そのものを深めるなら `mfg-improvement-frameworks` に渡す。

## この層で分かっていないこと

- IATF の条項番号と要旨は規格書で照合していない
- 各コアツール手引書の最新版の状況（APQP の改訂など）を確認していない
- IATF の SI（公式解釈）・FAQ の内容を反映していない
- 顧客ごとの CSR（トヨタ系・欧米 OEM 等）は一切入っていない
